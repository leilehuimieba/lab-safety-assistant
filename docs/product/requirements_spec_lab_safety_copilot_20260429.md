## 1. 文档说明

### 1.1 文档目的

本文档定义 Lab Safety Copilot 的完整功能需求、非功能需求、用户角色与场景，作为后续设计、开发、测试和验收的统一依据。

### 1.2 背景

项目最初定位为"基于 Dify + RAG 的实验室安全问答系统"（v8.2 演示基线）。经需求重定位后，产品方向切换为：

> 面向高校实验教学和科研实验的轻量级实验前安全检查助手。学生在开工前输入实验内容，系统自动识别风险、生成检查清单、判断是否需要阻断，并把高风险事项提交给老师确认。

Dify 不再作为核心依赖，保留为可选历史链路。

### 1.3 术语定义

| 术语 | 说明 |
|---|---|
| 开工前检查 | 实验开始前，学生对实验安全条件进行的自查流程 |
| 阻断 | 因高风险或关键安全条件缺失，系统判定不可开工 |
| 老师审核包 | 高风险实验提交给老师的摘要信息，含风险项、缺失项、建议动作 |
| 低置信队列 | 系统无法可靠回答的问题集合，需人工补充知识 |
| 来源引用 | 回答中标注信息来源（来源单位、文件、链接） |

## 2. 产品定位

### 2.1 产品愿景

补足现有 EHS 平台和 AI 问答之间的空缺——解决"学生准备开工前 5 分钟到底能不能做"的即时决策问题。

### 2.2 核心价值主张

1. **即时风险判断**：输入实验场景，秒级输出风险等级和阻断结论
2. **可操作检查单**：自动生成可勾选的开工前安全确认清单
3. **老师审核闭环**：高风险实验自动推送老师确认，形成审核记录
4. **知识可追溯**：所有安全建议标注信息来源
5. **安全兜底**：不确定时不硬答，进入待补知识队列

### 2.3 不做范围

- 不做完整 EHS 平台（不代替全校安全管理系统）
- 不做全量危化品库存管理
- 不做采购审批、门禁联动、IoT 实时监控
- 不做正式 SSO / 组织架构
- 不让 AI 直接承担最终安全许可责任
- 不强制接入 Dify / MCP

## 3. 用户角色

### 3.1 角色定义

| 角色 | 代号 | 核心诉求 | 使用频率 |
|---|---|---|---|
| 学生 / 新进实验人员 | STUDENT | 快速判断实验是否安全、知道该检查什么 | 每次实验前 |
| 教师 / 实验室负责人 | TEACHER | 审核高风险实验、查看培训完成情况 | 每日 |
| 实验室管理员 / 安全员 | ADMIN | 查看风险热点、管理知识缺口、导出报告 | 每周 |
| 系统维护人员 | MAINTAINER | 更新知识库、维护规则、监控运行状态 | 按需 |

### 3.2 角色详细描述

#### STUDENT（学生 / 新进实验人员）

- 痛点：不知道实验前该检查什么；SOP/SDS 冗长不愿看；不确定是否必须问老师
- 需要：输入实验信息 → 获得风险等级和检查单 → 明确是否需老师确认 → 事故时看到应急卡片
- 典型场景：每天实验课前 5 分钟完成自查

#### TEACHER（教师 / 实验室负责人）

- 痛点：重复提醒学生安全事项；高风险实验缺统一审核视图；学生理解程度不明
- 需要：查看待审核实验 → 看高风险摘要和缺失项 → 快速批准/驳回 → 导出记录
- 典型场景：课前/课后批量审核学生自查结果

#### ADMIN（实验室管理员 / 安全员）

- 痛点：安全资料分散；低置信问题无沉淀；高风险和阻断原因无统计
- 需要：看板总览 → 风险热点 → 低置信队列 → 缺失 SOP/SDS 识别 → 周报导出
- 典型场景：每周安全检查与汇报

### 4.2 P0 功能（MVP 必须实现）

#### FR-01 安全问答

**优先级**：P0
**所属角色**：STUDENT, TEACHER, ADMIN

**功能描述**：
用户通过自然语言提出实验室安全问题，系统从本地知识库检索相关条目，返回带来源引用的答案。

**输入**：
- 问题文本（1-4000 字符）
- 模式选择：lab（正式问答）/ agent（通用助手）

**处理流程**：
1. 文本预处理与分词
2. 安全规则匹配（safety_rules.yaml）—— 检查硬阻断、应急重定向、需补充信息
3. 本地知识库混合检索（文本 token 匹配 + bge-m3 语义检索）
4. 低置信度判断
5. 返回答案 + 引用列表 + 风险等级 + 决策标签

**输出**：
- 答案文本
- 决策类型：`llm_answer` / `rule_blocked` / `emergency_redirect` / `need_more_info` / `llm_low_confidence`
- 风险等级：`Low` / `Medium-Low` / `Medium` / `High` / `Critical`
- 匹配的规则 ID 和动作
- 低置信标记与原因
- 引用列表（kb_id, title, source_org, source_url, risk_level, snippet, score）

**验收标准**：
- 安全相关提问能在 2 秒内返回带来源引用的答案
- 硬阻断规则（refuse action）命中时，返回保守回答而非危险建议
- 应急意图（redirect_emergency）命中时，优先引导至应急卡片
- 低置信时标记 `low_confidence=true` 并提示联系老师

**关联 API**：`POST /api/chat`, `GET /api/search`

---

#### FR-02 风险评估

**优先级**：P0
**所属角色**：STUDENT

**功能描述**：
用户输入实验场景描述，系统综合规则严重性、知识库引用风险等级和关键词，计算风险评分（1-5），识别危险类型，推荐 PPE 和处置步骤。

**输入**：
- 实验场景描述（1-6000 字符）

**处理流程**：
1. 知识库检索（top_k=5）
2. 规则匹配
3. 风险评分计算：`max(规则严重性评分, 引用最高风险评分, 关键词评分)`
4. 危险类型识别（基于 HAZARD_HINTS 词典）
5. PPE 推荐（基于 PPE_HINTS 词典）
6. 低置信度评估

**输出**：
- 风险评分（1-5）
- 风险等级标签
- 关键危险点列表
- 推荐 PPE 列表
- 禁止事项列表
- 应急处置步骤
- 推荐操作步骤
- 引用列表

**验收标准**：
- 输入"锂电池拆解"应返回 High 或 Critical 风险等级
- 输入"用水稀释浓硫酸"应标记禁止事项（应将浓硫酸加入水中，非反操作）
- 危险类型识别准确率 ≥ 80%
- 核心测试场景阻断正确率 ≥ 90%

**关联 API**：`POST /api/risk/assess`, `POST /api/risk_assess`

---

#### FR-03 开工前检查清单

**优先级**：P0
**所属角色**：STUDENT

**功能描述**：
基于风险评估结果，自动生成个性化的开工前安全确认清单。学生逐项勾选确认，系统根据关键项完成情况判定是否允许开工。

**3.1 清单生成**

输入实验场景 → 系统生成包含以下基础项的检查清单：

| 检查项 ID | 内容 | 是否关键 |
|---|---|---|
| sop_reviewed | SOP / SDS / 实验目的已阅读 | 是 |
| label_verified | 试剂名称 / 浓度 / 标签已核对 | 是 |
| ppe_ready | PPE 已穿戴且适用 | 是 |
| containment_ready | 通风 / 防护 / 围堵措施到位 | 是 |
| emergency_ready | 应急设备（喷淋 / 洗眼器 / 灭火器 / 逃生通道）确认 | 是 |
| waste_route_ready | 废液分类和暂存路径确认 | 否 |

根据危险类型追加专项检查项（如 Chemical → 化学品不相容性和防漏托盘）。

高风险场景（评分 ≥ 4）追加：
- 导师批准或双人核对已完成
- 非单人操作或已获批的升级路径可用

**3.2 提交与评估**

学生提交勾选结果后：
- 所有关键项已勾选 → `allow_start=true`, 自动批准
- 任一关键项未勾选 → `allow_start=false`, 生成阻断原因列表, 状态为 `pending`（待老师审核）

**验收标准**：
- MVP 覆盖至少 6 种危险类型的专项检查项
- 所有关键项未勾选时 `allow_start=false`
- 阻断原因可读、可操作（不是纯技术术语）
- 提交记录持久化到 CSV

**关联 API**：`POST /api/checklist/template`, `POST /api/checklist/submit`

---

#### FR-04 老师审核

**优先级**：P0
**所属角色**：TEACHER

**功能描述**：
老师查看待审核的高风险实验开工申请，获得结构化摘要（学生 / 实验 / 风险等级 / 缺失项 / 系统建议），可批准或驳回。

**审核摘要信息**：
- 学生 / 操作人
- 实验场景
- 风险等级和评分
- 关键危险点
- 阻断原因（缺失的关键检查项）
- 审批状态

**老师操作**：
- 批准（approve）：实验可开工
- 驳回（reject）：附驳回理由

**验收标准**：
- 老师能在 30 秒内看懂风险和缺失项
- 待审核记录按时间倒序排列
- 批准/驳回操作即时生效并更新 CSV 记录
- 驳回时可附带文字说明

**关联 API**：`PATCH /api/checklist/{record_id}/review`

---

#### FR-05 管理看板

**优先级**：P0
**所属角色**：ADMIN

**功能描述**：
展示近期安全运行状况总览，包括核心指标、高风险场景、低置信问题和事故摘要。

**看板内容**：

| 模块 | 内容 |
|---|---|
| 核心指标 | 近期检查单数量、待审核数量、通过率、培训通过率 |
| 低置信 Top N | 知识不足最多的类别及数量 |
| 近期高风险场景 | 最近 N 条高风险/阻断的开工检查记录 |
| 事故摘要 | 按状态统计事故数量 |
| 逾期事故 | 逾期未处理的事故列表 |

**支持筛选**：
- 天数范围（默认 30 天）
- 风险等级过滤
- 事故状态过滤

**验收标准**：
- 看板数据实时反映本地 CSV 文件最新状态
- 支持 CSV 和 Markdown 周报导出
- 筛选参数有效

**关联 API**：`GET /api/admin/dashboard`, `GET /api/admin/export.csv`, `GET /api/admin/weekly_report.md`

### 4.3 P1 功能（MVP 延伸实现）

#### FR-06 应急卡片

**优先级**：P1
**所属角色**：STUDENT, TEACHER

**功能描述**：
用户描述事故场景或症状，系统匹配最相关的应急卡片并展示处置流程。

**应急卡片字段**：
- 标题、类别、摘要
- 触发征兆
- 立即处置步骤
- 禁止事项
- 所需 PPE
- 升级上报流程

**匹配方式**：bge-m3 语义检索 + 文本 token 匹配（混合模式）

**已有卡片**：化学品溅入眼睛、实验室火灾、触电、化学品泄漏

**验收标准**：
- 4 张卡片均能通过中文查询正确匹配
- 匹配结果包含处置步骤、禁止事项和升级流程
- 不确定时返回低置信标记

**关联 API**：`GET /api/emergency/cards`, `GET /api/emergency/match`

---

#### FR-07 培训考核

**优先级**：P1
**所属角色**：STUDENT, TEACHER, ADMIN

**功能描述**：
从题库随机抽取题目生成考核会话，学生作答后自动评分；老师/管理员可查看成绩统计和花名册完成情况。

**7.1 考核流程**：
1. 请求题目 → 获取 N 道随机选择题（含选项、是否多选、参考资料）
2. 提交答案 → 自动评分（比对正确选项索引）
3. 返回成绩 → 分数、是否通过、薄弱类别、推荐动作、逐题回顾

**7.2 统计与花名册**：
- 培训统计数据：尝试次数、通过率、平均分、类别错误分布
- 花名册功能：
  - 上传花名册 CSV（student_id, name, class_name, lab_group, required_training）
  - 查看完成状态（已完成/已通过/未完成人数及名单）
  - 下载花名册模板

**验收标准**：
- 题库不少于 20 题
- 题目随机抽取，每次会话不重复
- 评分准确（逐题比对正确选项）
- 花名册导入导出正常

**关联 API**：`GET /api/training/questions`, `POST /api/training/submit`, `GET /api/training/stats`, `GET /api/training/roster_status`, `POST /api/training/roster_upload`

---

#### FR-08 事故复盘

**优先级**：P1
**所属角色**：TEACHER, ADMIN

**功能描述**：
记录和跟踪实验室安全事故/事件，支持创建、更新、查询和删除，以及逾期状态自动计算。

**事故记录字段**：
- 标题、场景描述、严重级别、地点
- 原因类别、立即处置措施、纠正措施
- 负责人、截止日期
- 状态流转：`open` → `in_review` → `action_in_progress` → `verified` → `closed`
- 自动计算：复发风险、是否逾期、逾期天数

**验收标准**：
- 全生命周期 CRUD 正常
- 支持按状态和逾期筛选
- 逾期状态自动计算

**关联 API**：`GET /api/incidents`, `POST /api/incidents`, `PATCH /api/incidents/{id}`, `DELETE /api/incidents/{id}`

---

#### FR-09 低置信问题队列

**优先级**：P0（与安全问答联动）
**所属角色**：ADMIN

**功能描述**：
当知识库检索的 top 分数低于阈值（默认 3.5）时，该问题自动进入低置信队列，不硬答，提示联系老师。管理员可查看队列并标记状态。

**队列字段**：
- 创建时间、问题内容、模式
- 低置信原因
- 引用数量和 top 分数
- 建议通道、建议动作
- 状态（open / in_review / resolved）、备注

**验收标准**：
- 知识不足时自动入队，不输出可能危险的答案
- 队列可在看板中查看
- 支持导出 CSV

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 | 备注 |
|---|---|---|
| 知识库检索响应时间 | < 500ms（纯文本）, < 3s（含语义检索） | 不含首次模型加载 |
| API 端到端响应时间 | < 5s（P95） | 含 LLM 调用 |
| 前端首屏加载 | < 2s | Vite 构建产物 |
| 并发用户数 | ≥ 10（MVP 阶段） | 单机部署 |

### 5.2 可靠性

| 指标 | 目标值 |
|---|---|
| API 可用性 | 非生产环境 99% uptime |
| 知识库检索 fallback | 语义检索失败时自动降级为纯文本检索 |
| 数据持久化 | CSV/JSON 文件，每次写入立即刷盘 |
| 启动时间 | < 5s（不含首次 embedding 索引构建） |

### 5.3 安全性

| 要求 | 说明 |
|---|---|
| 不输出危险指导 | 规则引擎硬阻断 + 低置信兜底 |
| 安全责任不交给 AI | 所有输出为"建议""提示"，非最终许可 |
| 密钥管理 | API Key 通过环境变量注入，不提交到仓库 |
| 输入校验 | 所有 API 输入 Pydantic 校验，限制长度 |

### 5.4 可维护性

| 要求 | 说明 |
|---|---|
| 代码结构 | FastAPI router + service 分层，单文件 ≤ 500 行 |
| 测试覆盖 | 核心链路 100% 有 pytest 覆盖 |
| 配置管理 | 环境变量 + YAML 规则文件，不硬编码 |
| 数据可迁移 | CSV 格式，可直接用 Excel 打开编辑 |
| Docker 化 | 提供 Dockerfile + docker-compose.yml 一键部署 |

### 5.5 可观测性

| 要求 | 说明 |
|---|---|
| 健康检查 | `/health` 端点 |

## 6. 数据需求

### 6.1 知识库

- 格式：CSV（`knowledge_base_curated.csv`）
- 当前规模：398 条（v8.2 基线，导入成功数）
- 字段：id, title, question, source_title, source_org, source_url, risk_level, category, subcategory, hazard_types, answer, steps, forbidden, emergency, ppe, tags
- 质量要求：字段完整率 ≥ 95%，来源可追溯率 ≥ 90%

### 6.2 安全规则

- 格式：YAML（`safety_rules.yaml`）
- 内容：规则列表，每条含 id, severity, patterns, action, response 等
- 动作类型：refuse（拒绝）, redirect_emergency（应急重定向）, ask_for_more_info（追问）

### 6.3 种子数据

- 应急卡片：`web_demo/data/emergency_cards.json`（4 张）
- 培训题库：`web_demo/data/training_question_bank.json`（20+ 题）

### 6.4 运行时数据

- 低置信队列：`artifacts/low_confidence_followups/data_gap_queue.csv`
- 检查单运行记录：`artifacts/checklists/checklist_runs.csv`
- 培训尝试记录：`artifacts/training/training_attempts.csv`
- 培训错题记录：`artifacts/training/training_mistakes.csv`
- 事故记录：`artifacts/incidents/incident_reviews.csv`
- Embedding 索引缓存：`.cache/embedding/`

## 7. 用户场景与验收用例

### 场景 1：学生高风险实验自查被阻断

```
前置条件：知识库已加载
操作步骤：
  1. 学生输入场景："锂电池拆解，使用金属工具，未查看 SOP"
  2. 系统返回风险评估：High 或 Critical
  3. 系统生成检查清单（含电气安全、火灾防护专项项）
  4. 学生故意不勾选 PPE、SOP、导师批准三项
  5. 提交 → allow_start=false, 阻断原因列出三项
  6. 老师工作台出现待审核记录
预期结果：学生看到明确阻断提示和补做事项
```

### 场景 2：低风险实验自动通过

```
前置条件：知识库已加载
操作步骤：
  1. 学生输入场景："使用 pH 试纸测试自来水，已阅读 SOP，已穿实验服"
  2. 系统返回风险评估：Low 或 Medium-Low
  3. 学生勾选全部关键项
  4. 提交 → allow_start=true, 自动批准
预期结果：学生可开工，无需老师审核
```

### 场景 3：老师审核高风险实验

```
前置条件：存在一条待审核的检查单记录
操作步骤：
  1. 老师查看看板，看到待审核数量 ≥ 1
  2. 查看详情摘要：风险等级、缺失项、系统建议
  3. 老师驳回，附言："请先确认电池已完全放电"
预期结果：记录状态变为 rejected
```

### 场景 4：应急卡片匹配

```
前置条件：emergency_cards.json 已加载
操作步骤：
  1. 用户输入："眼睛被酸溅到了"
  2. 系统匹配到 chemical_splash 卡片
预期结果：返回洗眼器使用步骤、禁止揉眼提示、上报流程
```

### 场景 5：低置信兜底

```
前置条件：知识库无"纳米材料合成"相关内容
操作步骤：
  1. 用户提问："纳米材料合成需要注意什么安全问题？"
  2. 系统检索分数低于阈值
预期结果：
  - low_confidence=true
  - 答案包含"建议联系老师确认"
  - 问题进入低置信队列
```

## 8. 项目约束

1. **部署环境**：Windows 11 开发，Linux (Docker) 生产，Python 3.12/3.13
2. **不引入重型基础设施**：不依赖 Kubernetes、消息队列、分布式缓存
3. **MVP 数据存储**：优先 CSV/JSON 文件，后续可选 SQLite
4. **前端**：Vite + TypeScript + Tailwind CSS SPA，构建产物为纯静态文件
5. **测试框架**：pytest，核心链路必须有回归测试
6. **知识库语言**：简体中文为主，英文术语保留原文
7. **项目优先级**：课程/大创展示 > prod 正式上线

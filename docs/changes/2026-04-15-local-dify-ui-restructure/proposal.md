## 日期
2026-04-15

## 当前状态
- active

## 背景 / 问题
- 用户当前不希望继续把所有功能堆在同一个长页面里，而是希望本地 Dify 版项目朝“更像可交付产品”的方向推进。
- 现有 `web_demo/templates/index.html` 把问答、风险评估、清单、应急、培训、看板、事故复盘全部堆在一个页面中，结构过长，不利于展示、也不利于后续继续扩展本地 Dify 与知识库能力。
- 当前需要先建立更清晰的前端信息架构，例如侧边栏导航、分页/分区展示，再承接后续本地 Dify 搭建和知识库优化。

## 服务阶段
- 当前阶段：Phase 1 - 演示主链路固化（补充本地可交付界面结构）

## 目标
- 将当前单页长页面改造成“侧边栏 + 分区/分页”的结构。
- 优先收敛首页信息架构，使主导航更清晰，避免全部功能同屏堆叠。
- 为后续继续做本地 Dify、知识库和页面体验优化留出更合理的前端骨架。

## 非目标
- 本次不重建完整前端工程框架。
- 本次不把页面迁移到 React / Next.js。
- 本次不直接完成纯本机 Dify 单机部署。
- 本次不完成知识库内容重写，只做结构承接与后续任务入口。

## 范围
- 包含：
  - `web_demo/templates/index.html`
  - 必要的前端样式与原生 JS 结构调整
  - `docs/changes/` 当前 change 文档
- 不包含：
  - `web_demo/app.py` 大规模业务逻辑改造
  - 服务器部署脚本
  - 知识库大批量内容清洗

## 影响面
- 影响模块：
  - `web_demo` 展示层
  - 本地演示入口体验
- 影响演示链路：
  - 直接影响“展示入口是否清晰、页面是否像成型产品”
- 影响发布 / 验证链路：
  - 主要影响界面验证，不直接影响 release 流程

## 验收标准
- [ ] 页面已从单页堆叠改成侧边栏导航结构
- [ ] 至少已拆分出清晰的功能分区 / 分页视图
- [ ] 主要功能仍可访问，不因结构调整而失效
- [ ] 当前默认展示页更聚焦，不再把全部能力同时铺开

## 风险
- 风险 1：原生 HTML + JS 改造时，可能出现事件绑定与显示状态耦合问题
- 风险 2：一次性重组过多区域，会扩大 diff 和验证成本

## 回退方案
- 回退点：回退到当前单页长页面版本
- 回退条件：若结构改造导致主功能无法调用或展示链路明显变差
- 回退步骤：
  1. 回退 `web_demo/templates/index.html`
  2. 保留本次 change 文档，记录失败原因
  3. 后续拆成更小的 UI 改造任务再推进

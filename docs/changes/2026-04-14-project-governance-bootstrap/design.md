# Design

## 目标概述
- 为实验室安全小助手建立一个轻量但长期可演进的项目治理底盘。

## 方案概要
- 新增 `AGENTS.md`、`docs/README.md`、`docs/INDEX.md`、`docs/roadmap.md` 作为统一入口层。
- 新增 `docs/changes/` 承接中等以上任务。
- 新增 `docs/templates/` 提供标准模板。
- 通过首个 active change 把本次治理动作本身纳入 change 工作区。

## 关键决策
- 决策 1：根 `README.md` 保持“项目介绍 + 快速运行”角色，不改为执行入口。
- 决策 2：将当前演示主线统一为 `v8.2`，将 prod / go-live 作为后续增强项。
- 决策 3：中等以上任务默认先建 change，再进入设计、实现或验证。
- 决策 4：默认输出格式统一为“当前状态 / 缺失项 / 下一步建议”。

## 影响模块
- `AGENTS.md`
- `docs/README.md`
- `docs/INDEX.md`
- `docs/roadmap.md`
- `docs/changes/`
- `docs/templates/`

## 对展示主线的影响
- 对演示链路：不直接改动链路，但会统一后续演示主线判断依据。
- 对门禁 / 验证：要求后续任务补 `verify.md` 证据。
- 对答辩材料：后续可基于统一主线收敛答辩口径。

## 风险与取舍
- 风险：短期内会多出几份治理文档，需要团队适应。
- 取舍：优先增加最小必要文件，不对现有目录大改。

## 未决问题
- 答辩时间和最终演示入口尚未写入路线图
- 后续是否需要把部分旧文档迁入 `docs/archive/` 仍待观察

## 不做项
- 本次不对现有发布包、脚本、服务实现做结构性调整
- 本次不引入额外依赖和自动化系统

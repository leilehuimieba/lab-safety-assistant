# Design

## 目标概述
- 把 `v8.2` 演示链路从“材料里分散存在”收敛成一份可直接执行的冻结文档。

## 方案概要
- 新增 `docs/ops/v8_2_demo_flow_freeze_cn.md` 作为 `v8.2` 演示主链路执行入口。
- 将冻结文档与现有答辩总口径、完整版脚本、3 分钟脚本互相对齐。
- 将当前主推进 change 切换到本任务，并把路线图当前阶段回切到 Phase 1。

## 关键决策
- 决策 1：以 `web_demo` 为当前主演示页面，以 `README.md` 为演示前置入口。
- 决策 2：固定一套主问题 / 主场景，不再鼓励现场临时换题。
- 决策 3：把“成功判定”和“最小保底主线”写死，方便彩排时快速判断是否达标。
- 决策 4：保留 `demo_freeze_runbook_cn.md` 作为答辩层面的异常切换文档，而新文档更偏“`v8.2` 演示主链路冻结”。

## 影响模块
- `docs/ops/v8_2_demo_flow_freeze_cn.md`
- `docs/roadmap.md`
- `docs/changes/INDEX.md`
- `docs/changes/active.txt`
- `README.md`

## 对展示主线的影响
- 对演示链路：直接固化展示入口、展示顺序和固定输入
- 对门禁 / 验证：复用已有 `v8.2` 发布总结与正式验收证据
- 对答辩材料：为后续彩排和删改提供更强的执行主线

## 风险与取舍
- 风险：存在与已有脚本表述重复的内容
- 取舍：优先新增一份明确执行文档，不去重写所有旧文档

## 未决问题
- 最终现场从 README 开始还是直接从 `web_demo` 开始，仍要看实际彩排体验
- 最终答辩使用 3 分钟还是 5-8 分钟版本，仍需后续定

## 不做项
- 本次不改 `web_demo` 业务逻辑
- 本次不改评测、发布或部署脚本

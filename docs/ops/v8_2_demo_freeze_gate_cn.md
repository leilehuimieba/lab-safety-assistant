# v8.2 演示链路最终冻结 Gate

> 用途：定义 `v8.2` 演示链路从“预冻结”升级为“最终冻结”前必须满足的最小条件。  
> 使用时机：完成至少一轮真实计时彩排后，用本文判断是否允许盖章。  
> 适用范围：课程展示 / 大创答辩 / 阶段汇报场景。

## 1. Gate 目标

本 Gate 只回答一个问题：

> **当前 `v8.2` 演示链路，是否已经稳定到可以作为正式上台默认版本。**

如果未满足本文条件，则只能继续维持“预冻结”，不得宣称“最终现场版已定”。

## 2. 最终冻结必须满足的 5 个条件

### Gate 1：至少完成 1 轮真实计时彩排

必须满足：
- 已完成至少 1 轮真实计时彩排
- 已填写彩排记录
- 彩排记录不是事后凭印象补写

对应证据：
- `docs/ops/v8_2_demo_rehearsal_round1_draft_cn.md` 或后续轮次记录

### Gate 2：现场主线已跑通

必须满足：
- 已完成默认主线：`web_demo` 总览 -> 问答 -> 阻断 -> 看板 -> 收口
- 或者虽有局部卡顿，但已按冻结规则完成安全切换
- 不允许出现“现场路径完全改写”

对应证据：
- 彩排记录中的“实际执行顺序”
- 彩排记录中的“分步骤记录”

### Gate 3：总时长在可接受范围内

必须满足以下之一：

1. 默认 4.5 - 5 分钟稳态版已跑进目标区间  
或
2. 虽略超时，但已明确下一步固定压缩策略且不影响正式展示

不满足情况：
- 真实彩排明显超时
- 只能依赖大量删减和现场发挥才能压进时间

对应证据：
- 彩排记录中的“计划总时长 / 实际总时长 / 是否超时”

### Gate 4：关键切换规则可执行

必须满足：
- 问答超时的处理方式已验证
- 清单卡顿的处理方式已验证或口头演练确认
- 事故复盘是否保留，已有明确结论

对应证据：
- 彩排记录中的“阈值触发记录”
- 彩排记录中的“本轮结论”

### Gate 5：统一收口口径稳定

必须满足：
- 能稳定讲出 `398 / 20/20 / 3/3 PASS`
- 能稳定讲出“剩余问题是延迟波动，不是正确率”
- 没有超讲 prod / 上线 / 商用稳定性

对应证据：
- 彩排录像 / 主讲记录
- 彩排记录中的“Step 7 / 指标收口”

## 3. 一票否决项

出现以下任一情况，不得盖章为“最终冻结”：

1. 没有真实计时彩排记录
2. 现场主线仍在 README / `web_demo` / 事故复盘之间摇摆
3. 问答、阻断、看板三段主价值链路没有形成稳定顺序
4. 收尾指标和性能口径仍不稳定
5. 仍需要临场自由发挥才能演完

## 4. 最小证据包

要申请从“预冻结”升级为“最终冻结”，至少要提供下面 4 类证据：

1. **执行依据**
   - `docs/ops/v8_2_demo_final_freeze_cn.md`
2. **彩排记录**
   - 至少 1 份真实计时彩排记录
3. **口袋执行卡**
   - `docs/ops/v8_2_demo_stage_card_cn.md`
4. **统一指标与背景依据**
   - `docs/eval/v8_2_release_summary.md`
   - `docs/eval/formal_acceptance_20260331.md`

## 5. 盖章结论格式

当满足 Gate 时，建议统一这样写：

### 结论
- `pass`

### 判定
- 允许将 `docs/ops/v8_2_demo_final_freeze_cn.md` 从“预冻结”升级为“最终冻结”

### 默认现场口径
- 默认入口：直接 `web_demo`
- 默认主线：总览 -> 问答 -> 阻断 -> 看板 -> 收口
- 事故复盘：默认不进主线，仅作可选扩展

如果不满足 Gate，则统一写：

### 结论
- `hold`

### 判定
- 继续保持“预冻结”，待补真实彩排或待补关键结论后再复核

## 6. 建议的最终冻结动作

若 Gate 通过，建议一次性完成以下动作：

1. 将 `docs/ops/v8_2_demo_final_freeze_cn.md` 中“预冻结”改成“最终冻结”
2. 在当前 change 的 `status.md` 中写明最终结论
3. 在当前 change 的 `verify.md` 中补真实彩排结果
4. 如有必要，在 `docs/roadmap.md` 中标记 Phase 1 Gate 已满足

# 实验室安全小助手用户使用手册

> 文档版本：v1.0  
> 形成日期：2026-04-21  
> 对应项目：实验室安全小助手（Lab Safety Assistant）  
> 当前基线：`v8.2`  
> 适用阶段：课程 / 大创展示优先阶段  
> 文档定位：作为当前项目正式用户使用手册，用于指导学生、实验人员、教师与管理人员在现阶段正确使用系统，并统一试点、展示和汇报时的操作口径。  

---

## 1. 文档目的

本手册用于说明“实验室安全小助手”在当前阶段的实际使用方式、适用对象、操作流程和注意事项，帮助项目参与人、试点用户和指导教师在不夸大系统能力的前提下，正确理解并使用系统。

本手册遵循以下原则：

1. 以当前 `v8.2` 演示基线与现有项目文档为依据；
2. 以“当前真实可用能力”为主，不把规划内容写成既有功能；
3. 优先服务课程展示、试点使用、答辩讲解和阶段性应用验证；
4. 明确区分“可用功能”“推荐用法”“当前限制”。

---

## 2. 适用范围

本手册适用于以下场景：

1. 项目答辩与课程展示中的标准操作；
2. 实验室安全相关试点活动中的用户引导；
3. 学生进行实验前安全查询与基础学习；
4. 实验人员进行场景化风险判断与开工前检查；
5. 教师、实验室管理人员查看统计信息与组织试点使用。

本手册当前**不面向**以下范围：

1. 全校正式上线运行说明；
2. 大规模生产运维说明；
3. 与教务、资产、工单等外部系统的集成培训；
4. 移动端原生 App 使用说明。

## 3. 系统简介

### 3.1 系统一句话说明

实验室安全小助手是一个面向高校实验室场景的安全智能辅助系统，当前重点不是做泛化聊天，而是把实验室安全问答、开工前阻断、培训与看板、事故复盘等能力组织成一个可展示、可解释、可试点验证的闭环原型。

### 3.2 当前主要功能模块

当前系统围绕以下 5 个模块组织：

1. **平台总览**：展示项目定位、模块入口与当前阶段口径；
2. **智能问答**：围绕实验室安全问题给出结构化回答；
3. **准入阻断**：将安全建议转化为开工前检查和阻断判断；
4. **培训与看板**：支持培训展示与管理端统计信息查看；
5. **事故复盘**：提供事故记录与后续整改跟踪入口。

### 3.3 当前项目阶段定位

当前项目处于“课程 / 大创展示优先、试点准备和试点执行逐步补齐”的阶段，因此使用时应坚持以下理解：

1. 当前重点是**可运行、可展示、可答辩、可继续扩展**；
2. 当前已经形成较稳定的演示主线；
3. 当前最大的剩余问题是**延迟波动**，不是正确率口径缺失；
4. 当前不是把系统当作正式商用或全校长期运行平台使用。

### 3.4 当前统一项目口径

在项目介绍、试点说明和答辩中，建议统一使用以下口径：

- 知识库正式导入：`398`
- 正式回归：`20/20`
- 稳定性验证：`3/3 PASS`
- 当前主要待优化问题：**延迟波动，不是正确率问题**

## 4. 使用前准备

### 4.1 使用对象准备

不同角色在使用前建议完成以下准备：

1. **学生用户**：明确自己要问的是实验前安全问题、PPE、禁忌操作或应急处置；
2. **实验人员 / 助教**：准备好待执行实验的场景描述，便于生成检查清单；
3. **教师 / 管理员**：明确本次使用目标是演示、培训、试点还是反馈收集。

### 4.2 使用环境准备

进入系统前建议确认：

1. 本地或指定演示环境可访问；
2. 页面能够正常打开主界面；
3. 左侧可以看到至少以下模块：
   - 平台总览
   - 智能问答
   - 准入阻断
   - 培训与看板
4. 如用于正式展示，建议优先使用已冻结的标准主线，不临场切换题目。

### 4.3 推荐使用原则

为保证展示与试点效果，建议遵循以下原则：

1. 问题尽量围绕实验室安全，不使用泛化闲聊问题；
2. 场景描述尽量具体，如“高温回流”“有机溶剂加热”“危化品转移”等；
3. 对高风险实验，更推荐结合“智能问答 + 准入阻断”一起使用；
4. 对培训和试点，不只看回答内容，也要记录用户理解情况和反馈。

## 5. 系统主界面说明

### 5.1 平台总览

平台总览主要用于：

1. 快速说明项目定位；
2. 展示当前版本和阶段口径；
3. 说明系统不是普通聊天页，而是实验室安全闭环原型；
4. 帮助首次使用者先建立整体认知。

适用对象：

- 教师
- 管理员
- 首次接触系统的学生或试点参与人

### 5.2 智能问答

智能问答用于围绕实验室安全主题提出问题，例如：

1. 某类危险实验开始前最关键的阻断项是什么；
2. 某类危化品如何储存或转运；
3. 某类事故发生时应如何应急处置；
4. 某类实验操作中应佩戴哪些防护装备。

当前问答结果一般用于：

- 获得结构化安全建议；
- 辅助理解实验前的关键风险点；
- 为后续准入阻断页面生成检查逻辑提供上下文。

### 5.3 准入阻断

准入阻断模块用于把安全要求转化为开工前检查项，并在关键条件不满足时给出阻断结论。

该模块的核心价值不在于“建议更多”，而在于：

1. 识别关键项；
2. 判断是否满足开工前条件；
3. 当关键项缺失时明确提示“暂不可开工”；
4. 给出阻断原因和下一步建议。

### 5.4 培训与看板

培训与看板主要用于：

1. 展示培训通过率、阻断率等管理视角信息；
2. 展示低置信问题和最近高风险场景；
3. 帮助教师或管理员判断当前知识库与培训内容是否需补充；
4. 为试点阶段形成可汇报数据做准备。

### 5.5 事故复盘

事故复盘模块用于展示事故记录、整改责任与时限等闭环思路。

当前阶段应注意：

1. 事故复盘是系统闭环的一部分；
2. 当前演示主线通常不把该模块作为重点；
3. 在无现成记录时，可作为“系统能力边界和后续扩展方向”的说明项，不宜夸大为已有大量运行数据。

## 6. 学生用户使用指南

### 6.1 适用人群

适用于：

1. 首次进入实验室的学生；
2. 需要进行实验前安全学习的学生；
3. 需要快速查询某类风险点、PPE 或应急要求的学生。

### 6.2 推荐使用目标

学生用户建议重点完成以下任务：

1. 了解实验前的关键安全要求；
2. 学会围绕具体场景提问；
3. 理解哪些情况会触发“不能开工”；
4. 参加培训或配合试点问卷反馈。

### 6.3 标准使用步骤

#### 第一步：先查看平台总览

建议首次使用时，先进入“平台总览”，了解：

1. 系统是做什么的；
2. 系统有哪些功能模块；
3. 当前系统不是泛化聊天工具，而是实验室安全辅助系统。

#### 第二步：进入智能问答

在“智能问答”页面中，学生用户可围绕自己的实验场景提问。推荐问题类型包括：

1. “危险实验开始前最关键的阻断项是什么？”
2. “乙醇应如何储存？”
3. “浓酸溅到手上怎么办？”
4. “进行高温回流实验前需要注意什么？”

提问建议：

1. 问题尽量具体；
2. 尽量带上实验场景；
3. 不要只问“安全吗”这类过于宽泛的问题。

#### 第三步：查看回答并提取关键信息

学生在阅读回答时，建议重点关注：

1. 哪些是必须满足的前置条件；
2. 哪些是禁止事项；
3. 哪些是 PPE 或操作规范；
4. 哪些是事故发生后的应急动作。

#### 第四步：理解准入阻断逻辑

如果问题涉及高风险实验，建议继续进入“准入阻断”模块，理解系统为什么会对某些实验给出“暂不可开工”的判断。

学生在这一阶段应理解：

1. 系统不是只给参考建议；
2. 某些关键项不满足时，实验应被直接阻断；
3. 阻断的目的是帮助降低开工前风险，而不是增加形式化流程负担。

#### 第五步：参与培训或反馈

在试点或课堂展示中，学生完成主要操作后，建议：

1. 配合填写满意度问卷；
2. 说明自己最容易理解或最难理解的模块；
3. 提出希望系统补充的内容。

### 6.4 学生用户常见误区

1. 把系统当成普通聊天机器人使用；
2. 只看回答，不看其中的“禁止/阻断”含义；
3. 使用过于模糊的问题，导致场景不明确；
4. 把系统建议直接替代教师指导或实验室制度要求。

## 7. 实验人员 / 助教使用指南

### 7.1 适用人群

适用于：

1. 参与实验操作的学生骨干或实验人员；
2. 实验课程助教；
3. 需要在实验开始前完成安全检查的使用者。

### 7.2 推荐使用目标

实验人员 / 助教建议重点完成以下任务：

1. 围绕真实实验步骤做场景化提问；
2. 生成检查清单；
3. 对关键项是否满足做判断；
4. 在试点中记录系统是否帮助自己更快识别风险。

### 7.3 推荐使用流程

#### 步骤一：用具体实验场景发起提问

建议输入包含以下信息的描述：

1. 实验类型；
2. 是否涉及高温、高压、危化品、易燃溶剂等；
3. 是否为夜间操作、单人操作或连续加热等场景。

例如：

- “夜间进行高温回流和有机溶剂加热实验，开工前最关键的检查项是什么？”
- “转移易燃溶剂前，需要确认哪些安全条件？”

#### 步骤二：阅读风险点并确认关键条件

对问答结果，建议不要只看结论，应进一步确认：

1. 是否点出了高风险条件；
2. 是否提出了必须满足的前置要求；
3. 是否存在一票否决项。

#### 步骤三：进入准入阻断模块生成清单

在准入阻断模块中，实验人员 / 助教应重点关注：

1. 系统生成了哪些检查项；
2. 哪些项目属于关键项；
3. 若关键项缺失，系统给出的阻断原因是什么；
4. 是否给出了下一步补救建议。

#### 步骤四：进行提交并理解结果

提交清单后，通常会出现两类结果：

1. **允许继续准备或开工**：表示关键项基本满足；
2. **清单阻断，暂不可开工**：表示仍有关键条件未满足。

对第二类结果，应优先把它理解为一种风险提示与门禁逻辑，而不是页面报错。

#### 步骤五：记录使用反馈

在试点中，实验人员 / 助教建议记录：

1. 哪个模块最有帮助；
2. 哪个判断最符合真实使用习惯；
3. 哪些清单项表述还不够清晰；
4. 是否存在响应等待偏长的情况。

### 7.4 常见使用建议

1. 对高风险实验，尽量固定使用“问答 + 阻断”双模块；
2. 不建议只看问答而跳过关键检查逻辑；
3. 对课堂演示，建议使用固定问题，减少现场不确定性；
4. 如页面响应偏慢，不要连续重复点击，先等待结果或切换到下一展示环节。

## 8. 教师 / 管理员使用指南

### 8.1 适用人群

适用于：

1. 指导教师；
2. 实验室负责人；
3. 试点组织者；
4. 项目汇报或答辩中的管理视角讲解人。

### 8.2 推荐使用目标

教师 / 管理员建议重点关注：

1. 系统是否能服务安全管理，而不仅是单条问答；
2. 是否能通过看板识别薄弱点；
3. 是否能在试点中积累满意度和应用证据；
4. 是否能作为课程展示和后续课题推进材料的一部分。

### 8.3 推荐操作流程

#### 第一步：先从平台总览建立统一口径

教师 / 管理员在给学生或试点对象介绍时，建议先说明：

1. 这不是普通聊天页面；
2. 当前是实验室安全闭环原型；
3. 当前项目重点是可展示、可试点、可继续扩展。

#### 第二步：结合智能问答说明知识支撑作用

在智能问答模块中，教师 / 管理员应重点强调：

1. 当前问答围绕实验室安全知识组织；
2. 回答更关注安全要求和前置条件；
3. 问答不是最终目的，关键是后续可以转入阻断和管理视角。

说明口径建议使用“知识库支撑 + 规则约束”的表达，避免把系统描述为无边界的泛化 AI。

#### 第三步：在准入阻断模块强调管理价值

教师 / 管理员在展示该模块时，建议强调：

1. 平台区别于普通问答的核心价值，在于把建议变成门禁条件；
2. 系统可以围绕当前实验问题生成检查项；
3. 当关键项不满足时，会明确提示不能开工；
4. 这有助于培养学生对“前置条件”的理解。

#### 第四步：在培训与看板模块查看管理信息

教师 / 管理员建议重点查看以下几类信息：

1. 清单阻断率；
2. 培训通过率；
3. 低置信问题；
4. 最近高风险场景。

这几类信息的作用主要是：

- 判断学生在哪些问题上仍理解不足；
- 判断知识库和培训内容哪些部分需要补强；
- 为试点汇总和课题汇报提供材料。

#### 第五步：组织试点记录与反馈回收

在试点场景中，教师 / 管理员建议同步完成：

1. 签到记录；
2. 使用场景记录；
3. 满意度问卷回收；
4. 问题清单与改进建议整理。

当前项目在申报推进中，试点证据和满意度统计是重要缺口，因此教师 / 管理员使用系统时，不应只停留在“看过演示”，而应尽量同步沉淀材料。

## 9. 标准演示使用建议

### 9.1 推荐演示顺序

在答辩、汇报或课堂展示中，推荐采用以下顺序：

1. 平台总览
2. 智能问答
3. 准入阻断
4. 培训与看板
5. 指标收口

### 9.2 推荐固定问题

为减少现场不确定性，建议优先使用以下固定问题：

- `危险实验开始前最关键的阻断项是什么？`

必要时可补充：

- `浓酸溅到手上怎么办？`
- `乙醇应如何储存？`
- `气瓶如何固定？`

### 9.3 演示时建议强调的核心信息

演示时建议反复强调以下几点：

1. 这不是泛化聊天；
2. 回答围绕实验室安全知识和规则组织；
3. 平台真正的价值是把建议转成开工前阻断；
4. 平台不只服务个人，也服务教师与管理员；
5. 当前项目已经达到“可演示、可答辩、可继续扩展”的状态。

### 9.4 演示中遇到响应偏慢时的处理建议

如果问答结果等待较久，可采用以下处理方式：

1. 不临时更换题目；
2. 不连续多次重复点击；
3. 直接切换到准入阻断模块，说明系统价值不只在回答，而在门禁逻辑；
4. 最后用统一指标口径收尾。

## 10. 试点使用建议

### 10.1 单场试点推荐结构

每次试点建议采用以下结构：

1. 5 分钟：介绍系统定位与边界；
2. 10~15 分钟：用户完成 1~2 个固定问题和 1 次清单阻断体验；
3. 5 分钟：查看培训与看板；
4. 5 分钟：回收满意度问卷与开放反馈。

### 10.2 试点记录重点

每次试点建议至少记录：

1. 日期与场景；
2. 参与人数；
3. 用户角色；
4. 使用模块；
5. 主要反馈；
6. 需要优化的问题。

### 10.3 试点过程中应避免的问题

1. 把系统包装成已经全面成熟的正式平台；
2. 在试点现场临时展示大量未验证的新功能；
3. 不做签到、不回收问卷，导致无法沉淀证据；
4. 不区分“用户体验意见”和“正式安全制度要求”。

## 11. 常见问题（FAQ）

### 11.1 这个系统是不是普通聊天机器人？

不是。当前系统聚焦实验室安全问答、准入阻断、培训看板和复盘闭环，不以泛化闲聊为目标。

### 11.2 回答内容是否可以直接替代老师指导或实验室制度？

不建议这样理解。系统的作用是提供结构化辅助与风险提示，正式实验要求仍应以实验室制度、教师指导和现场规范为准。

### 11.3 为什么有时响应会比较慢？

当前项目的主要剩余问题是延迟波动，而不是正确率问题。在展示和试点中，建议使用固定主线，不因短时等待而频繁切换问题。

### 11.4 为什么有时展示环境和本地环境表现不完全一样？

当前不同环境下，问答链路可能存在“正式知识链路”与“结构化回退链路”的差异。对外说明时应以当前实际环境为准，不应把某一环境下的配置状态写成所有环境都完全一致。

### 11.5 为什么事故复盘模块有时没有可展示的记录？

因为当前阶段事故复盘更多体现为闭环设计的一部分，并非所有环境下都已有丰富历史记录。展示时可说明其定位，但不宜夸大现有数据积累。

### 11.6 目前项目最能说明完成度的指标是什么？

当前统一口径为：知识库正式导入 `398`、正式回归 `20/20`、稳定性验证 `3/3 PASS`。

## 12. 注意事项

### 12.1 使用边界注意事项

1. 当前系统适合展示、试点、课程和阶段性应用验证；
2. 当前不应宣传为已完成全校正式上线；
3. 当前不应将未来规划内容描述为已交付能力。

### 12.2 内容理解注意事项

1. 问答结果应结合实验室制度理解；
2. 对高风险实验，重点应放在关键前置条件与阻断判断；
3. 培训和看板中的数据更适合作为趋势观察与试点证据，而不是最终管理考核系统。

### 12.3 展示组织注意事项

1. 建议使用固定问题和固定主线；
2. 不建议现场自由扩题过多；
3. 不建议现场进入后台配置、部署细节或临时排障环节；
4. 若用于申报推进，应同步保留签到、记录表、问卷和结果汇总材料。

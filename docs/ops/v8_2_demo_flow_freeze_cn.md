# v8.2 演示主链路冻结文档

> 用途：作为 `v8.2` 演示链路的当前唯一执行入口。  
> 优先级：当演示顺序、固定问题、固定场景与其他答辩脚本冲突时，以本文为准。  
> 当前目标：保证“可复现、可切换、可解释”的展示主链路。

> 补充说明：若当前任务是“正式上台展示”，则进一步以 `docs/ops/v8_2_demo_final_freeze_cn.md` 为现场唯一执行入口。
> 说明：本文保留的是“完整冻结视图”，用于收敛演示链路全貌；不等同于正式现场默认只走的最短稳态主线。

## 1. 当前主入口

### 主入口
1. `README.md`
2. `web_demo`

### 次级入口
如果现场时间极紧或仓库首页加载不顺，可直接从 `web_demo` 开始。

### 不建议作为主入口
- Dify 后台工作流页面
- go-live / prod readiness 文档
- 服务器部署页面

原因：这些内容更偏支撑证据，不是当前课程 / 大创展示的主入口。

## 2. 当前默认彩排版本

### 默认版本
- 默认使用：**5 分钟左右标准版**
- 适用场景：大多数课程汇报、大创中期 / 结题展示、老师现场追问概率较高的答辩

### 压缩版本
- 压缩使用：**3 分钟快演版**
- 适用场景：展示时间被明显压缩、前面团队超时、老师要求快速过主价值链路

### 当前固定规则
- 如果现场没有明确压时指令，**一律按 5 分钟标准版准备**。
- 如果现场主持老师明确要求“快一点”“只看核心能力”，立即切到 3 分钟快演版。
- 不再临场自由决定“讲长版还是短版”，必须先在开始前选定一个版本。

## 3. 当前冻结后的标准主线

按以下顺序固定展示：

1. README 首页
2. `web_demo` 首页总览
3. 问答
4. 开工前检查清单
5. 管理端看板
6. 事故复盘
7. 指标收口

### 3.1 标准版推荐时长
- Step 1：README，20-30 秒
- Step 2：`web_demo` 首页总览，15-20 秒
- Step 3：问答，50-70 秒
- Step 4：开工前检查清单，50-70 秒
- Step 5：管理端看板，40-60 秒
- Step 6：事故复盘，30-45 秒
- Step 7：指标收口，20-30 秒

### 3.2 压缩版保留顺序
如果切到 3 分钟版，只保留：

1. `web_demo` 首页总览
2. 问答
3. 开工前检查清单
4. 管理端看板
5. 指标收口

事故复盘改成一句口头说明，不再现场展开。

## 4. 固定问题与固定场景

### 3.1 主问题
`危险实验开始前最关键的阻断项是什么？`

### 3.2 问答备用问题
- `高风险实验可以一个人单独做吗？`
- `实验开始前要检查什么？`
- `乙醇应如何储存？`

### 3.3 固定风险 / 清单场景
`夜间进行高温回流和有机溶剂加热实验`

### 3.4 看板必须指出的指标
- 清单阻断率
- 培训通过率
- 低置信问题
- 最近高风险场景

### 3.5 事故复盘必须指出的字段
- 事件经过
- 原因分类
- 整改措施
- 责任人
- 截止日期
- 当前状态 / 逾期提醒

## 5. 每一步的成功判定

### Step 1：README
成功条件：
- 已展示项目名
- 已展示 `v8.2`
- 已展示核心能力
- 已展示统一指标

### Step 2：`web_demo` 首页
成功条件：
- 已向评审指出问答、风险评估、清单、看板、事故复盘位置

### Step 3：问答
成功条件：
- 已成功输入主问题
- 已展示回答
- 已口头说明“知识库 + 模型 + 规则约束”的主链路

### Step 4：开工前检查清单
成功条件：
- 已生成清单
- 已展示至少一次阻断

### Step 5：管理端看板
成功条件：
- 已指出至少 3 类核心指标
- 已说明平台不只服务问答，还服务管理

### Step 6：事故复盘
成功条件：
- 已展示一条记录，或已明确说明字段设计与闭环作用

### Step 7：指标收口
成功条件：
- 已讲出 `398 / 20/20 / 3/3 PASS`
- 已讲出“当前剩余问题是延迟波动”

## 6. 彩排版切换阈值

以下阈值用于现场快速切换，避免陷入等待或排障：

### 阈值 A：README 不顺
- 如果 README 在 **10 秒内** 没有顺利展示，直接跳过 README，切 `web_demo`

### 阈值 B：问答等待过长
- 如果问答在 **15 秒内** 没有返回有效结果，直接切到开工前检查清单
- 不重复追问超过 **1 次**

### 阈值 C：清单操作卡顿
- 如果清单生成或提交连续 **1 次** 不顺，不做第二轮完整重试
- 直接口头说明阻断逻辑，并切到管理端看板

### 阈值 D：事故复盘无现成记录
- 如果 **10 秒内** 找不到可展示记录，直接口头说明字段设计，不继续翻找

### 阈值 E：总时长已逼近上限
- 如果讲解已到总时长上限前 **1 分钟**，立即切到“指标收口”

## 7. 彩排版执行前检查

正式彩排或正式展示前，至少确认下面 6 项：

1. 已明确本轮使用 **5 分钟标准版** 还是 **3 分钟快演版**
2. 主问题和备用问题已固定，不临场换题
3. 清单场景已固定为 `夜间进行高温回流和有机溶剂加热实验`
4. 看板优先讲的 4 个指标已固定
5. 收尾口径已固定为 `398 / 20/20 / 3/3 PASS + 延迟波动`
6. 已明确是否展示事故复盘；若不展示，提前切到备用链路

## 8. 最小保底主线

如果现场时间紧张或页面波动，必须保住下面这条主线：

1. `README.md`
2. `web_demo`
3. 问答
4. 开工前检查阻断
5. 管理端看板
6. 指标收口

只要这 6 步完成，就视为本轮演示主线成功。

## 9. 备用链路

### 备用链路 A：不展示 README
适用情况：
- 仓库首页打不开
- 时间被压缩

切换方式：
- 直接进入 `web_demo`
- 开场口头补一句项目定位和当前基线

### 备用链路 B：不展示事故复盘
适用情况：
- 时间不足
- 事故复盘列表没有现成记录

切换方式：
- 事故复盘改成口头说明模块作用
- 直接进入指标收口

### 备用链路 C：问答后直接切阻断与看板
适用情况：
- 问答响应慢
- 问答效果一般

切换方式：
- 不纠缠问答结果
- 直接强调“先保住最能体现平台价值的阻断和管理能力”

### 备用链路 D：直接使用 3 分钟快演版
适用情况：
- 主持人明确要求快速演示
- 前序团队超时，留给本项目时间明显不足
- 彩排判断现场更适合讲“主价值链路”而不是“全模块覆盖”

切换方式：
- 不再展示 README
- 不再展开事故复盘
- 只保留 `web_demo` 总览、问答、阻断、看板、指标收口

## 10. 当前固定收尾口径

建议始终这样收口：

“今天我们重点展示的不是一个泛化聊天机器人，而是一条已经收敛到 `v8.2` 的实验室安全闭环演示链路。当前它已经把问答、风险评估、开工阻断、管理看板和事故复盘串了起来，并且已经拿到 `398` 条导入、`20/20` 正式回归、`3/3 PASS` 稳定性证据。下一阶段我们会继续扩充高价值正式知识源，并进一步压缩延迟波动。”

## 11. 彩排记录最低要求

每轮真实彩排后，至少补 5 项记录：

1. 本轮使用的版本：5 分钟标准版 / 3 分钟快演版
2. 实际是否按冻结顺序完成
3. 哪一步触发了备用链路
4. 总时长是否超时
5. 下一轮要微调的唯一重点

如果没有这 5 项记录，就不应宣称“彩排版已经稳定”。

### 配套记录文件
- 模板：`docs/ops/demo_rehearsal_record_template_cn.md`
- 首轮预填稿：`docs/ops/v8_2_demo_rehearsal_round1_draft_cn.md`

建议做法：
- 第一次真实彩排直接基于“首轮预填稿”填写
- 第二轮及之后统一复制“模板”生成新一轮记录

## 12. 当前不纳入主链路的内容

以下内容不纳入本次演示主链路：

- prod readiness 通过
- 服务器正式上线
- go-live 预检
- 本地模型切换
- 生产级持续运行

这些内容只能作为“后续方向”提及，不作为当前演示主线的一部分。

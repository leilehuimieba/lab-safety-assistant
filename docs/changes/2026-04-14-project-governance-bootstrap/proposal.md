2026-04-14-project-governance-bootstrap

## 日期

## 当前状态

## 背景 / 问题
- 当前仓库已有 README、评测、运维、发布、状态文档，但缺少唯一执行入口。
- 历史文档中同时存在 `v7`、`v8.1`、`v8.2` 等口径，AI 续做时容易误判当前主线。
- 仓库缺少中等以上任务的标准 change 工作区，后续多轮协作容易丢状态、丢验证、丢边界。

## 服务阶段
- Phase 0 - 治理底盘收口

## 目标
- 建立唯一执行入口与阶段路线图
- 建立 change 工作区规范与模板
- 建立 AGENTS.md 协作规则
- 将当前执行主线统一收敛为 `v8.2` 演示基线 + 课程 / 大创展示优先

## 非目标
- 不修改业务代码
- 不重构现有脚本、演示服务和发布链路
- 不解决当前 prod / go-live 的所有阻塞项

## 范围
- 包含：
  - `AGENTS.md`
  - `docs/README.md`
  - `docs/INDEX.md`
  - `docs/roadmap.md`
  - `docs/changes/`
  - `docs/templates/`
- 不包含：
  - 业务功能实现
  - 数据包重做
  - 演示服务逻辑重写

## 影响面
- 影响模块：项目规范、文档入口、AI 协作方式
- 影响演示链路：间接影响，主要体现在后续推进口径统一
- 影响发布 / 验证链路：间接影响，主要体现在后续 verify 归档与阶段判断更稳定

## 验收标准
- [ ] 唯一执行入口已建立
- [ ] 当前阶段与当前主线已明确
- [ ] change 工作区已建立
- [ ] 首个 active change 已可用于续做
- [ ] AI 协作规则已写入 `AGENTS.md`

## 风险
- 规范与已有文档可能暂时存在重复信息
- 若后续不持续更新 `status.md` / `verify.md`，规范会失效

## 回退方案
- 回退点：仅保留新增规范文件，不动原有业务文件
- 回退条件：若规范引发明显混乱或与现有流程冲突
- 回退步骤：冻结新增规范文件的使用，恢复为根 README + 现有 docs 分散推进

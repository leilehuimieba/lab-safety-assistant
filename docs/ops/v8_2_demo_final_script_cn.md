## 2. Step 2：智能问答（55 - 70 秒）

### 固定输入
- 模式：`实验室安全助手`
- 固定问题：`危险实验开始前最关键的阻断项是什么？`

### 操作
1. 左侧点击：`智能问答`
2. 确认单选为：`实验室安全助手`
3. 输入固定问题：`危险实验开始前最关键的阻断项是什么？`
4. 点击：`运行问答`
5. 等页面出现：`链路=dify-workflow`

### 必须指出
- 当前走的是实验室安全正式知识链路
- 回答不是自由发挥，而是知识库支撑 + 规则约束
- 回答核心点是：**关键前置条件未满足时一律不得开工**

### 建议话术
“这里先展示正式问答链路。系统会先从实验室安全知识库里检索，再结合模型生成回答，所以它不是泛泛聊天，而是围绕高风险实验的前置条件来回答。当前这条问题给出的核心判断是：只要关键前置条件不满足，就必须一票否决，不能开工。”

### 成功判定
- 页面出现回答正文
- 页面出现：`链路=dify-workflow`

### 备用话术
如果 15 秒还没出结果：
“问答链路今天我先不在这里等待太久，直接切到更能体现平台价值的准入阻断模块。这个项目的重点不只是回答问题，而是把建议真正变成禁止开工条件。”

## 3. Step 3：准入阻断（55 - 70 秒）

### 操作
1. 左侧点击：`准入阻断`
2. 指给评审看：页面已经继承上一页当前问题
3. 如页面尚未显示清单，点击：`基于当前问题生成清单`
4. **不要勾选关键项**，直接点击：`提交清单`
5. 展示页面结果：`清单阻断，暂不可开工`

### 必须指出
- 这里不是“给建议”，而是“给阻断”
- 只要关键项没满足，系统就不允许开工
- 这一步是平台区别于普通问答的核心价值

### 建议话术
“真正能体现平台价值的，不是回答更像聊天，而是把安全要求变成开工前阻断条件。这里我们不去人为勾选关键项，而是直接提交，系统就会明确告诉我们：当前不能开工，而且会把阻断原因列出来。”

### 成功判定
- 页面出现：`清单阻断，暂不可开工`
- 页面能展示阻断原因

### 备用话术
如果清单没及时生成或提交不顺：
“这一页的核心价值不是表单本身，而是把安全建议变成开工门禁。即使现场不重复操作，我们也已经证明它会围绕当前问题生成清单，并在关键项未满足时阻断开工。”

## 4. Step 4：培训与看板（40 - 55 秒）

### 操作
1. 左侧点击：`培训与看板`
2. 只看管理端看板区域，不展开培训答题流程
3. 只指出 4 类信息：
   - 清单阻断率
   - 培训通过率
   - 低置信问题
   - 最近高风险场景

### 必须指出
- 平台不只服务单次问答，也服务老师和管理员
- 管理端看板能反推：哪些问题需要补知识库、哪些场景风险更高
- 当前浏览器级走查中，页面可直接看到 `90% / 0% / 5 条 / 最近高风险场景列表`
- 如果具体数值现场有波动，仍只讲类别，不纠结数值解释

### 建议话术
“平台不只服务单次问答，也服务管理端。这里重点不在于某一个静态数字，而在于四类管理信息已经被沉淀出来：阻断率、培训情况、低置信问题，以及最近高风险场景。当前这一版页面里，我们可以直接看到清单阻断率、培训通过率、低置信积压和高风险场景列表。也就是说，系统不仅能答、能拦，还能反向驱动后续管理和知识补强。”

### 成功判定
- 已指出这 4 类信息
- 已完成“个人使用 -> 管理使用”的价值抬升

## 6. 当前唯一允许的现场切换规则

### 规则 A：问答超时
- 问答等待超过 **15 秒**，立刻切 `准入阻断`
- 不再追第二个问题

### 规则 B：阻断页操作不顺
- 清单生成 / 提交连续 **1 次** 不顺，不做第二轮完整尝试
- 直接解释阻断逻辑，切 `培训与看板`

### 规则 C：总时长逼近上限
- 如果剩余时间不足 **1 分钟**，直接进入指标收口

### 规则 D：事故复盘默认不进主线
- 只有老师明确追问“复盘怎么做”，才打开事故复盘页
- 否则一律不进主线

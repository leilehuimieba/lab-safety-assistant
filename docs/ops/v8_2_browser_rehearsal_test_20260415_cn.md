# v8.2 浏览器自动化主线测试记录（2026-04-15）

> 用途：记录一次 **模拟人为点击网页** 的浏览器自动化测试结果。  
> 说明：本次测试已覆盖“打开页面、输入问题、点击按钮、触发阻断、刷新看板”的主要交互，但**不等于带主讲话术的人工计时彩排**。  
> 关联 change：`docs/changes/2026-04-14-v8-2-demo-flow-freeze/`

## 1. 测试目标

本次测试重点验证：

1. `web_demo` 页面能否正常打开
2. 当前正式主线中的“问答 -> 阻断 -> 看板”是否可通过浏览器交互跑通
3. 关键页面反馈是否能在 UI 上被看到，而不只是接口返回
4. 当前页面真实展示的是正式链路还是 fallback

## 2. 测试环境

- 日期：2026-04-15
- 本地地址：`http://127.0.0.1:8088`
- 浏览器方式：Playwright Python 脚本（headless）
- 服务状态：本地 `uvicorn` 已启动

## 3. 测试主线

按以下顺序执行：

1. 打开首页
2. 检查首页 meta 信息
3. 输入主问题并点击“运行问答”
4. 输入固定场景并点击“生成开工清单”
5. 故意留 1 个关键项未勾选，点击“提交清单”
6. 点击“刷新看板”
7. 确认事故复盘区块可见

## 4. 关键结果

### 4.1 首页总览

- 结果：**通过**
- 页面标题：`实验室安全助手平台`

### 4.2 首页 meta

- 结果：**通过**
- 页面展示：
  - 当前版本：`defense-freeze-20260331`
  - 验收状态：`已封版 / 20/20`
  - 知识库规模：`398 导入 / 96 本地`
  - 实验室问答链路：`Dify 未配置，当前处于结构化回退模式`

### 4.3 问答

- 结果：**通过**
- 主问题：`危险实验开始前最关键的阻断项是什么？`
- 页面返回耗时：约 `173.6 ms`
- 页面路由信息：
  - `链路=fallback-rule-engine`
  - `决策=llm_fallback_structured`

结论：
- 页面层面问答能正常返回
- 但当前页面实际展示的仍然是 **fallback**，不是 Dify 正式链路

### 4.4 清单生成

- 结果：**通过**
- 场景：`夜间进行高温回流和有机溶剂加热实验`
- 页面展示：
  - `风险=高 (4/5)`
  - `危险源=Chemical, Fire`
- 复选框数量：`10`
- 生成耗时：约 `186.8 ms`

### 4.5 阻断提交

- 结果：**通过**
- 做法：故意留空一个关键项
- 页面返回耗时：约 `91.8 ms`
- 页面状态：
  - `清单阻断，暂不可开工`

结论：
- 阻断在页面上能直接看到
- 阻断原因和下一步建议能直接展示给评审

### 4.6 看板刷新

- 结果：**通过**
- 页面刷新耗时：约 `1578.2 ms`
- 页面已能显示：
  - 清单阻断率
  - 培训通过率
  - 培训平均分
  - 未闭环复盘数
  - 逾期整改数
- 低置信问题区块可见
- 最近高风险场景区块可见
- 事故汇总区块可见

### 4.7 事故复盘区块

- 结果：**通过**
- 事故复盘模块在页面中可见
- 但本次未做“创建 / 更新事故复盘记录”的交互

## 5. 自动化测试结论

### 通过项

- 首页可打开
- 页面 meta 可展示
- 问答按钮可正常触发
- 清单按钮可正常触发
- 阻断在 UI 上可见
- 看板能刷新并展示关键指标

### 当前最关键观察

1. **当前浏览器真实展示仍然是 fallback，不是 Dify 正式链路**
2. **阻断链路是目前页面最稳、最适合现场展示的价值步骤**
3. **看板展示在页面上是成立的，但现场仍需控制讲解时长**

## 6. 本次测试不能替代什么

以下内容，本次自动化测试**仍不能**直接替代：

1. 主讲人口头讲解是否顺
2. 人工实际计时是否稳定在 4.5 - 5 分钟
3. 评审视角下页面切换是否自然
4. 正式环境下是否能切回 Dify 正式链路

因此：

- 本次测试可以视为 **T10-1 的强前置证据**
- 但仍建议至少补 1 次人工浏览器计时彩排，再进入 freeze gate

## 1. 报告目的

本报告用于系统性回答以下问题：

1. 当前项目已经测试了什么；
2. 当前项目有哪些“已验证通过”的能力；
3. 当前项目的测试证据来自哪里；
4. 当前项目距离申报书完整验收还差哪些测试与评估项；
5. 当前阶段应如何向老师、评委和后续维护者说明项目真实完成度。

本报告不追求把未来计划写成当前事实，而是坚持：

1. 以现有仓库证据为基础；
2. 以当前 `v8.2` 展示基线为统一口径；
3. 区分“演示可用”“验证通过”“完整结题验收仍待补齐”的不同层级。

## 6. 测试方法分类

### 6.1 发布与回归测试

目标：

1. 验证正式发布包可用；
2. 验证 20 题正式回归结果；
3. 验证安全拒答、应急处理、覆盖率等关键指标。

### 6.2 稳定性测试

目标：

1. 验证正式回归结果是否具有重复性；
2. 验证 `20/20` 不是偶然结果；
3. 观察尾部延迟波动情况。

### 6.3 API 级预检

目标：

1. 验证本地服务是否可启动；
2. 验证主展示流程对应的关键 API 是否可用；
3. 提前发现浏览器彩排前的硬阻塞问题。

### 6.4 浏览器级验证

目标：

1. 验证页面点击层面的问答、阻断、看板主线可跑通；
2. 验证默认展示主线是否与脚本一致；
3. 验证浏览器级证据是否齐备。

### 6.5 文档与主线冻结验证

目标：

1. 验证演示主入口、固定问题、成功判定、最小保底主线和备用链路是否明确；
2. 验证脚本、执行卡、verify 清单和 freeze gate 是否齐备；
3. 确保演示不再依赖临场拼接多份材料。

# 当前产品定位摘要（2026-05-01）

## 1. 一句话定位

**实验安全前置哨（Lab Safety Copilot）** 是面向高校实验教学和科研实验的轻量级实验前安全决策系统。

它让学生在开工前输入实验内容和准备状态，系统自动识别风险、生成检查清单、输出能否开工的结构化结论，并在高风险或缺关键条件时提交老师审核。

## 2. 当前不是做什么

当前主线不再是：

1. 基于 Dify 的 RAG 问答机器人。
2. 以申报书 `1000/3000` 条知识库扩容为第一目标的数据工程。
3. 大而全的 EHS 平台。
4. 危化品库存 / 采购 / 门禁 / IoT 系统。
5. 单纯展示 `v8.2` Dify workflow 的答辩 demo。

这些内容可以作为历史资产或后续增强，但不作为当前 no-Dify MVP 的 Gate。

## 3. 当前要解决的核心问题

学生开工前真正需要的是：

```text
这个具体实验，在我当前准备条件下，到底能不能做？
如果不能做，缺了什么？
如果风险高，是否必须找老师确认？
```

普通 AI 问答只能给文字建议；本项目要给出结构化安全判断。

## 4. 当前 MVP 闭环

```text
实验场景输入
  ↓
规则引擎识别硬阻断
  ↓
本地知识库检索来源
  ↓
风险等级与危险类型识别
  ↓
生成开工前检查清单
  ↓
输出允许 / 需老师确认 / 暂不可开工
  ↓
老师审核包
  ↓
管理看板和低置信队列
```

## 5. 当前关键设计原则

1. **规则先于模型**：安全边界由 YAML 规则和结构化判断承担，不依赖 prompt。
2. **AI 不做最终许可**：系统给出辅助判断，高风险最终由老师确认。
3. **本地优先**：主链路应不依赖 Dify；Dify 只作为可选兼容链路。
4. **可追溯**：回答、风险判断和检查结果都尽量保留来源、原因和记录。
5. **先闭环再扩展**：先把实验前自查、阻断、审核、看板跑通，再做登录、数据库、试点和平台化。

## 1. 项目定位

项目名称：**基于 Dify 搭建 RAG 增强的大语言模型实验室安全小助手系统**。

本项目面向高校实验室安全管理场景，建设一个基于 Dify、RAG、结构化知识库和安全规则的智能问答与管理辅助系统。系统应能够整合实验室安全制度、MSDS、SOP、应急预案、设备操作规范等资料，为学生、实验人员、教师和管理员提供安全问答、风险提示、应急引导、培训学习、统计看板和持续优化能力。

本需求文档将申报书中的目标转换为可开发、可验收、可追踪的工程需求。申报书中的“首创”“100%”“99%+”等表述在内部作为目标或挑战项管理；对外汇报时应以实际评测集、试点范围和验证证据为准，避免无证据的绝对化宣传。

## 2. 建设目标

### 2.1 总体目标

构建一套可部署、可演示、可评测、可持续更新的实验室安全小助手系统，实现：

1. 使用自然语言进行实验室安全问答。
2. 基于结构化知识库和 RAG 检索生成答案。
3. 对高风险问题进行过滤、拒答、保守提示或转人工。
4. 支持知识库动态更新和来源追溯。
5. 提供用户友好的 Web 交互界面。
6. 建立量化评估体系，用数据持续优化系统。
7. 在试运行环境中收集反馈并形成结题验收材料。

### 2.2 申报书四大核心模块

| 模块 | 申报书要求 | 工程化解释 |
|---|---|---|
| 结构化知识库 | 构建不少于 3000 条结构化知识库 | 建立统一字段模板，覆盖 MSDS、SOP、应急预案、设备操作、PPE、废弃物、制度规范等类别，支持导入 Dify 和本地检索 |
| LLM + RAG | 微调或配置 LLM 并集成 RAG 技术 | 以 Dify 工作流为正式问答链路，结合关键词检索、语义检索、规则护栏和 fallback 链路；微调可作为后续增强项，不阻塞当前交付 |
| 交互界面 | 开发符合用户习惯的交互界面 | 提供 Web Demo / 产品预览界面，覆盖问答、风险评估、准入阻断、培训、老师工作台、管理员看板、事故复盘 |
| 量化评估体系 | 建立量化评估体系持续优化 | 建立离线评测集、回归脚本、发布门禁、低置信问题队列、试点反馈和验收报告 |

## 3. 用户角色

| 角色 | 主要诉求 | 主要功能 |
|---|---|---|
| 学生 / 新进实验人员 | 快速知道实验是否安全、遇到事故怎么办、培训是否通过 | 安全问答、风险评估、开工前检查、培训答题、应急卡片 |
| 实验人员 / 课题组成员 | 在实验准备与执行前获得规范提示 | SOP/PPE/试剂风险查询、准入检查、应急流程 |
| 教师 / 实验室负责人 | 查看高风险操作、培训完成情况、待审核开工记录 | 老师工作台、高风险清单、未完成培训名单、审核建议、导出处理清单 |
| 管理员 / 验收负责人 | 管理知识库、查看运行指标、导出验收材料 | 管理看板、知识库状态、证据链接检查、周报/验收包、评测结果 |
| 发布与维护人员 | 持续更新知识库和评测集，保证系统稳定运行 | 数据采集、清洗、发布、回归测试、门禁、回滚 |

## 4. 功能需求

### FR-01 结构化安全知识库

**目标**：按申报书要求建设不少于 3000 条结构化知识条目。

必须包含：

1. 知识条目唯一 ID。
2. 标题 / 问题 / 场景描述。
3. 安全类别：危化品、设备操作、PPE、防火防爆、废弃物、应急处置、实验室制度、生物安全、电气安全、辐射安全等。
4. 风险等级。
5. 适用实验或适用场景。
6. 标准处置步骤。
7. 禁止事项。
8. PPE 要求。
9. 来源单位、来源文件、来源链接或来源说明。
10. 版本、更新时间、审核状态。

验收口径：

| 阶段 | 数量目标 | 质量要求 |
|---|---:|---|
| M1 | ≥1000 条核心知识 | 字段完整率 ≥95%，来源可追溯率 ≥90% |
| M2 | ≥2000 条扩展知识 | 覆盖至少 6 大类别，重复率受控 |
| M3 | ≥3000 条正式知识 | 可导入 Dify / 本地检索，抽检通过，形成构建报告 |

### FR-02 Dify + RAG 正式问答链路

**目标**：用户可通过自然语言提问，系统基于知识库和 RAG 返回可追溯答案。

必须支持：

1. Dify 知识库工作流作为正式问答链路。
2. 本地结构化 fallback 作为异常兜底。
3. 关键词检索 + 语义检索的混合召回能力。
4. 回答中显示来源、引用或知识条目编号。
5. 对低置信问题输出保守回答和人工复核提示。
6. 支持多轮追问的基础上下文衔接。

验收口径：

| 指标 | 申报书目标 | 当前工程验收口径 |
|---|---:|---|
| 有效回答率 | >95% | 在正式评测集上统计 pass / partial / fail，阶段目标先 ≥95% |
| 专业准确率 | 申报书写 >99%，阶段目标 ≥95% | 以专家审核题集为准，先达 ≥95%，>99% 作为挑战目标 |
| 响应时间 | <3 秒 | 本地 fallback 和缓存命中目标 <3 秒；Dify/云模型链路单独统计 P95 |
| 可追溯性 | 未量化 | 高风险/专业答案必须展示来源；普通答案来源展示率 ≥90% |

### FR-03 高风险安全过滤与人工干预

**目标**：危险问题不能被系统错误指导。

必须支持：

1. 高风险意图识别。
2. 危险操作、危险混配、违法违规内容拒答。
3. 应急类问题优先走应急模板或权威知识条目。
4. 低置信度时提示联系老师、管理员或安全负责人。
5. 形成危险问题评测集和拒答回归报告。

验收口径：

| 指标 | 目标 |
|---|---:|
| 高风险拒答召回率 | 阶段目标 ≥95%，挑战目标 100% |
| 危险答案放行数 | 正式发布评测中为 0 |
| 低置信提示覆盖 | 专业问题低置信时必须出现人工复核提示 |

### FR-04 风险评估与准入阻断

**目标**：用户输入实验场景后，系统输出风险等级、关键危险点、PPE、禁止事项和开工前检查清单。

必须支持：

1. 实验步骤 / 试剂 / 设备 / PPE 输入。
2. 输出风险等级和风险说明。
3. 生成开工前检查清单。
4. 对 SOP、SDS、PPE、试剂标签、老师审核等关键项进行阻断。
5. 高风险或关键项缺失时显示“先联系老师确认”。
6. 记录提交结果，用于老师和管理员看板。

验收口径：

1. 高风险场景 `allow_start = false`。
2. 未满足关键项时必须展示阻断原因。
3. 老师工作台可看到待审核或高风险记录。
4. 管理看板可统计阻断率和高风险场景。

### FR-05 应急处置与安全应急模板

**目标**：事故和紧急情况优先给出规范、简洁、可执行但不越权的应急引导。

必须支持：

1. 火灾、泄漏、灼伤、触电等常见应急卡片。
2. 通过关键词或语义方式匹配应急卡。
3. 输出先撤离、报警、断电、隔离、冲洗、上报等步骤。
4. 明确提示联系老师 / 实验室安全负责人 / 校内应急电话。
5. 对非专业人员不输出危险处置细节。

验收口径：应急题集通过率 ≥95%，关键场景不得漏掉“人身安全优先”和“及时上报”。

### FR-06 培训与学习

**目标**：支持实验室安全培训与考核。

必须支持：

1. 训练题库。
2. 抽题答题。
3. 自动评分。
4. 通过 / 未通过记录。
5. 老师查看未完成培训名单。
6. 管理员查看整体培训通过率。

验收口径：

1. 学生可完成一次答题并获得分数。
2. 老师可查看未完成名单。
3. 管理端可统计通过率。
4. 后续产品化阶段接入真实班级名单与身份认证。

### FR-07 管理端看板与报告

**目标**：管理员可掌握系统知识库、问答、风险、培训、事故和验收状态。

必须支持：

1. 知识库数量与导入状态。
2. 低置信问题队列。
3. 风险评估统计。
4. 培训统计。
5. 事故复盘记录。
6. 证据链接可访问状态。
7. 周报、CSV、验收包导出。

验收口径：至少能导出一份包含当前版本、知识库、评测、风险、培训、证据链接和下一步计划的验收包。

### FR-08 动态知识更新流程

**目标**：解决申报书中“知识滞后”和“新规同步”问题。

必须支持：

1. 采集：公开资料、校内制度、SOP、MSDS、应急预案。
2. 清洗：字段映射、去重、风险标签、来源保留。
3. 审核：人工抽检、低质量来源标记。
4. 发布：生成 Dify 导入包和本地检索数据。
5. 回滚：保留版本包，允许回退。
6. 监控：低置信问题进入补充知识流程。

验收口径：新资料从收集到可检索的流程可在 72 小时内完成；重要 MSDS/SOP 更新应形成更新记录。

### FR-09 试运行与反馈迭代

**目标**：按申报书要求完成试运行和用户反馈。

必须支持：

1. 至少 1 个 Web 试运行入口。
2. 至少 1 个实验室或课程场景试用。
3. 收集学生和老师反馈。
4. 根据反馈形成问题清单和迭代记录。
5. 形成结题报告、技术路线和推广建议。

验收口径：至少收集 3-5 名学生、1-2 名老师的真实使用反馈，并归档到 `docs/pilot/`。

## 5. 非功能需求

| 编号 | 需求 | 验收口径 |
|---|---|---|
| NFR-01 | 可追溯 | 高风险/专业答案必须附来源或条目编号 |
| NFR-02 | 可评测 | 每次发布有评测报告和门禁结果 |
| NFR-03 | 可部署 | 支持本地 Web Demo；后续支持 Docker / systemd 常驻 |
| NFR-04 | 可维护 | 知识库和规则库有版本包、发布记录和回滚说明 |
| NFR-05 | 安全可靠 | 危险问题不得输出可执行危险指导 |
| NFR-06 | 性能 | Dify 链路、fallback 链路分别统计 P50/P95；<3 秒为优化目标 |
| NFR-07 | 7×24 服务 | 需通过连续运行监控或 systemd/Docker 健康检查证明，不仅靠文档说明 |
| NFR-08 | 数据安全 | 正式试点前补登录、权限和审计，避免真实数据裸露 |

## 7. 版本路线

### Sprint A：申报书口径收敛（2026-04-28 至 2026-05-05）

交付物：

1. 本需求规格说明书。
2. 申报书目标与现状差距矩阵。
3. 新 change 工作区。
4. 统一指标计算口径。
5. 1000 / 3000 条知识库扩容计划。

Gate：所有申报书承诺均有“已完成 / 部分完成 / 待完成 / 后置”的明确状态。

### Sprint B：知识库扩容到 1000 条（2026-05-06 至 2026-05-20）

交付物：

1. ≥1000 条核心知识库。
2. 字段完整性报告。
3. 去重和来源抽检报告。
4. Dify 导入包或本地检索包。
5. 1000 条阶段评测报告。

Gate：核心类别覆盖，字段完整，能被问答链路检索使用。

### Sprint C：评测体系与安全门禁强化（2026-05-21 至 2026-06-05）

交付物：

1. 专业题集、安全拒答题集、应急题集、意图识别题集。
2. 有效回答率、专业准确率、拒答召回率、P95 延迟报告。
3. 低置信问题处理闭环。
4. 72 小时知识更新演练报告。

Gate：正式评测集达到阶段阈值，危险答案放行为 0。

### Sprint D：知识库扩容到 3000 条并试运行（2026-06-06 至 2026-06-25）

交付物：

1. ≥3000 条知识库正式包。
2. 真实试运行反馈。
3. 7×24 或连续运行证据。
4. 结题验收包。
5. 技术路线和推广建议。

Gate：满足申报书核心交付物：软件系统 + 技术路线 + 评测 / 试运行证据。

### Sprint E：结题收口（2026-06-26 至 2026-06-30）

交付物：

1. 结题报告。
2. 最终演示脚本。
3. 用户手册。
4. 部署与运维手册。
5. 指标与证据汇总。

## 8. 暂不作为当前核心阻塞的事项

以下内容出现在申报书或扩展设想中，但不作为 2026-06-30 前的核心阻塞：

1. LoRA 微调和联邦知识协同。
2. 区块链追溯。
3. IoT 环境监控和违规识别硬件联动。
4. 校园统一身份认证正式对接。
5. 飞书 / 微信公众号正式上线。
6. 多校区复制部署。

这些可作为“后续研究与推广方向”。

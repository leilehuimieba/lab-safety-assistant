# 实验室安全小助手产品化优化方案

> 目标：从“可演示项目”优化为“竞品用户愿意长期使用的实验室安全工具”。

## 1. 核心判断

当前系统已经能演示问答、风险评估、开工检查、培训看板等能力，但长期使用还不够省事。

用户真正需要的不是理解系统模块，而是快速得到：

1. 能不能做；
2. 为什么；
3. 下一步做什么；
4. 依据是什么；
5. 有没有记录可以留存。

## 2. 产品定位

不是普通 AI 问答工具，而是：

> 面向高校实验室安全的“问答 + 风险判断 + 开工检查 + 培训留痕”工作台。

## 3. 主要问题

| 问题 | 影响 |
|---|---|
| 首页仍有系统展示感 | 新用户不知道马上该做什么 |
| 问答结果偏文本 | 用户看完还要自己判断 |
| 开工检查卖点不够突出 | 没体现和普通 AI 的差异 |
| 留痕能力弱 | 老师、管理员难以用于真实管理 |
| 角色边界不清 | 学生、老师、管理员看到的重点混在一起 |
| 反馈入口不足 | 系统答错后无法持续改进 |

## 4. 优化优先级

### P0：先做主流程

1. 问答结果改成“决策卡片”
   - 能不能做；
   - 风险等级；
   - 原因；
   - 下一步按钮；
   - 依据来源。

2. 开工检查改成正式流程
   - 第一步：输入实验内容；
   - 第二步：生成检查项；
   - 第三步：判断能否开工；
   - 输出“可以开工 / 禁止开工 / 需要老师确认”。

3. 增加基础留痕
   - 保存本次问答；
   - 保存风险评估；
   - 保存开工检查；
   - 支持导出或复制记录。

### P1：增强长期使用

4. 增加角色模式
   - 学生：问答、检查、培训；
   - 老师：审核、查看高风险；
   - 管理员：统计、知识库、事故复盘。

5. 增加反馈纠错
   - 有用；
   - 没用；
   - 来源错误；
   - 需要人工确认。

6. 优化证据来源
   - 来源标题；
   - 来源机构；
   - 可访问状态；
   - 查看原文。

## 5. 本轮实施范围

本轮先做 P0，避免一次改太大：

1. 前端增加“安全决策卡片”；
2. 问答结果默认展示结论、风险、下一步；
3. 开工检查页面强化“禁止/允许/需确认”的状态展示；
4. 增加“保存本次记录”和“复制记录”按钮；
5. 增加简单反馈按钮。

## 6. 验收标准

完成后，用户输入一个实验场景，应该能在 1 分钟内看到：

1. 明确结论；
2. 主要风险；
3. 下一步建议；
4. 可点击依据；
5. 可保存或复制的记录。

# v8.2 人工计时彩排执行包（主讲 / 操作 / 记录 / Gate 盖章一体版）

> 用途：把“最后一轮主讲人口播计时彩排”收敛成一份可直接执行、可直接回填、可直接进入 Gate 判断的操作包。  
> 适用阶段：`docs/changes/2026-04-14-v8-2-demo-flow-freeze/` 的 T10 最后一段。  
> 当前前提：脚本与逐步话术已冻结，但**尚未完成最终人工计时彩排盖章**。  
> 正式脚本依据：`docs/ops/v8_2_demo_final_script_cn.md`  
> 正式冻结依据：`docs/ops/v8_2_demo_final_freeze_cn.md`

## 1. 本执行包解决什么问题

本执行包只解决最后 3 件事：

1. **怎么跑一轮标准人工计时彩排**
2. **彩排后怎么回填记录，不遗漏关键信息**
3. **怎么从“彩排完成”走到“freeze gate 判定 pass / hold”**

换句话说，这不是再重写脚本，而是把当前已经冻结的脚本真正跑一遍，并把结果收成最终盖章依据。

## 2. 当前唯一适用口径

### 唯一入口
- `http://127.0.0.1:8088`

### 唯一默认主线
- `平台总览 -> lab 问答 -> 准入阻断 -> 培训与看板 -> 指标收口`

### 唯一固定输入
- 问答模式：`实验室安全助手`
- 固定问题：`危险实验开始前最关键的阻断项是什么？`
- 固定收口：`398 / 20/20 / 3/3 PASS`

### 默认版本
- `4.5 - 5 分钟稳态版`

### 默认不进主线
- README
- 事故复盘完整流程
- Dify 后台页
- 服务器部署页
- prod / go-live 说明

## 3. 彩排角色分工

建议至少按下面 3 个角色执行：

### 角色 A：主讲人
负责：
- 严格按 `docs/ops/v8_2_demo_final_script_cn.md` 讲
- 不临场换题
- 不额外扩展 prod / 部署 / 商用话题
- 只在脚本允许的切换规则内切换

### 角色 B：操作人
负责：
- 只做页面点击与输入
- 不自行补讲
- 若触发切换阈值，只执行既定跳转
- 不现场排障

### 角色 C：记录人 / 计时人
负责：
- 从主讲人第一句开口开始计时
- 记录每一步开始时间、是否卡顿、是否触发阈值
- 彩排结束后立刻回填记录，不允许事后靠印象补写

> 若现场只有 2 个人，也可由“记录人”和“操作人”兼任，但计时必须有人负责。

## 4. 彩排开始前 2 分钟预检

只做以下检查，不额外扩 scope：

- [ ] `web_demo` 可打开：`http://127.0.0.1:8088`
- [ ] 左侧可见：平台总览 / 智能问答 / 准入阻断 / 培训与看板
- [ ] 智能问答默认可切到：`实验室安全助手`
- [ ] 本轮不打开 README / Dify 后台 / 部署页
- [ ] 记录文档已提前打开：`docs/ops/v8_2_demo_rehearsal_round1_draft_cn.md`
- [ ] verify 文档已准备：`docs/ops/v8_2_demo_verify_checklist_cn.md`
- [ ] gate 文档已准备：`docs/ops/v8_2_demo_freeze_gate_cn.md`

如果以上任一项不满足：
- 本轮不要标成“真实计时彩排完成”
- 只能标注为“预检未完成 / 条件不足”

## 5. 计时彩排执行顺序

## Step 0：计时起点
- **计时起点**：主讲人第一句“我直接从演示页开始”开口时
- **计时终点**：主讲人讲完收尾句“下一阶段重点不是再修正确率，而是继续压缩延迟波动，并扩充高价值正式知识源”

---

## Step 1：平台总览（目标 15 - 20 秒）

### 操作人动作
- 点击左侧：`平台总览`
- 保持页面稳定，不滚动，不切页

### 主讲人必须完成
- 说明这不是泛化聊天工具
- 说明这是实验室安全闭环原型
- 点出当前基线：`v8.2 / defense-freeze-20260331`

### 记录人要记
- 是否在 20 秒内完成
- 主讲是否一上来就讲散
- 是否错误打开了 README 或其他页

### 本步通过标准
- 评审能立刻知道“这不是普通聊天页”

---

## Step 2：lab 问答（目标 55 - 70 秒）

### 操作人动作
1. 点击：`智能问答`
2. 确认模式：`实验室安全助手`
3. 输入问题：`危险实验开始前最关键的阻断项是什么？`
4. 点击：`运行问答`
5. 等待页面结果

### 主讲人必须完成
- 明确这是正式知识链路
- 明确不是自由发挥
- 明确核心点：关键前置条件不满足就不能开工

### 记录人要记
- 是否出现 `链路=dify-workflow`
- 是否在 15 秒阈值内返回
- 若超时，是否按规则切到阻断页

### 本步切换规则
- **15 秒还没出有效结果**：直接切 Step 3
- 不追第二个问题
- 不在问答页现场排障

---

## Step 3：准入阻断（目标 55 - 70 秒）

### 操作人动作
1. 点击：`准入阻断`
2. 确认页面继承当前问题
3. 如未显示清单，点击：`基于当前问题生成清单`
4. **不要勾选关键项**
5. 直接点击：`提交清单`

### 主讲人必须完成
- 明确这一步不是建议，而是阻断
- 明确关键项不满足就不允许开工
- 把这一步讲成平台核心价值

### 记录人要记
- 是否出现：`清单阻断，暂不可开工`
- 是否成功展示阻断原因
- 是否因卡顿触发切换

### 本步切换规则
- 清单生成 / 提交连续 **1 次** 不顺：直接切 Step 4
- 不做第二轮完整尝试

---

## Step 4：培训与看板（目标 40 - 55 秒）

### 操作人动作
- 点击：`培训与看板`
- 只停留管理看板区域
- 不展开培训答题全过程

### 主讲人必须完成
- 只指出 4 类信息：
  1. 清单阻断率
  2. 培训通过率
  3. 低置信问题
  4. 最近高风险场景
- 明确平台同时服务管理端

### 记录人要记
- 是否能稳定指出 4 类信息
- 是否讲得过长
- 是否因为事故复盘诱惑而偏离主线

### 本步通过标准
- 完成“个人问答 -> 管理闭环”的价值抬升

---

## Step 5：指标收口（目标 20 - 30 秒）

### 主讲人必须讲出
- `398`
- `20/20`
- `3/3 PASS`
- “剩余问题是延迟波动，不是正确率问题”

### 记录人要记
- 四个收口点是否都讲到了
- 是否多讲了 prod / 上线 / 商用稳定性
- 总时长是否压在目标区间内

### 本步通过标准
- 用一句话把“已经完成什么 / 下一步是什么”收干净

## 6. 现场唯一允许的阈值处理

### 阈值 A：问答超时
- 标准：超过 15 秒还未出有效结果
- 动作：直接切阻断
- 记录：写明“已触发阈值 A”

### 阈值 B：阻断页操作不顺
- 标准：清单生成 / 提交连续 1 次不顺
- 动作：直接切看板
- 记录：写明“已触发阈值 B”

### 阈值 C：总时长逼近上限
- 标准：剩余时间不足 1 分钟
- 动作：直接收口
- 记录：写明“已触发阈值 C”

### 阈值 D：事故复盘无现成记录
- 标准：当前无稳定复盘样例
- 动作：默认不进入主线
- 记录：写明“事故复盘仍仅作扩展项”

## 7. 彩排结束后 10 分钟内必须做的事

按下面顺序执行，不能跳步：

### 7.1 回填真实彩排记录
直接打开并回填：
- `docs/ops/v8_2_demo_rehearsal_round1_draft_cn.md`

必须补齐：
- 日期
- 记录人 / 主讲人 / 操作人
- 实际执行顺序
- 每一步是否成功
- 实际总时长
- 最耗时步骤
- 最卡顿步骤
- 是否触发阈值
- 本轮结论
- 下一轮唯一微调重点

### 7.2 勾检 verify 提交清单
打开：
- `docs/ops/v8_2_demo_verify_checklist_cn.md`

判断本轮证据是否足够进入最终冻结复核。

### 7.3 执行 freeze gate 判定
打开：
- `docs/ops/v8_2_demo_freeze_gate_cn.md`

只输出两种结论之一：
- `pass`
- `hold`

## 8. Gate 结论怎么写

### 如果结果是 `pass`
统一写法建议：

- 结论：`pass`
- 判定：允许将 `docs/ops/v8_2_demo_final_freeze_cn.md` 从“待主讲人口播计时盖章”升级为“最终冻结”
- 默认口径：
  - 默认入口：直接 `web_demo`
  - 默认主线：总览 -> 问答 -> 阻断 -> 看板 -> 收口
  - 事故复盘：默认不进主线，仅作可选扩展

### 如果结果是 `hold`
统一写法建议：

- 结论：`hold`
- 判定：继续保持“待主讲人口播计时盖章”
- 缺口：只写 1 条下一轮唯一微调重点

## 9. 通过 Gate 后的一次性收口动作

若 `pass`，建议一次性完成下面 4 件事：

1. 更新 `docs/ops/v8_2_demo_final_freeze_cn.md`
   - 把“待主讲人口播计时盖章”改成“最终冻结”
2. 更新当前 change 的 `status.md`
   - 写明最终结论与时间
3. 更新当前 change 的 `verify.md`
   - 补真实计时彩排结果与 Gate 判断
4. 如需要，更新 `docs/roadmap.md`
   - 标注当前 Phase 1 的 demo freeze gate 已满足

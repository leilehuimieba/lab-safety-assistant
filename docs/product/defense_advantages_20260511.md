# 项目答辩优势提炼（2026-05-11）

## 一句话定位
**实验室安全小助手**不是“泛聊天机器人”，而是一个围绕“实验前能不能开工”构建的**安全决策助手**：先做实验前核查，再做风险分级，再输出检查清单、老师审核包和可追溯证据。

## 为什么它更有竞争力

### 1. 主线更聚焦
- 竞品/普通 Demo 往往停留在“问答能答”。
- 我们的主线是“**实验前安全闭环**”：  
  **输入实验信息 → 风险判断 → 开工建议 → 检查清单 → 老师审核 → 记录归档**。
- 这个主线非常适合答辩，因为能清楚回答“项目解决了什么具体问题”。

### 2. 不依赖重型平台，落地更稳
- 采用 **轻量单体 + 模块化**，而不是一上来就上微服务。
- 优势是：
  - 部署简单
  - 演示稳定
  - 开发成本更低
  - 更适合课程设计 / 大创 / 答辩场景

### 3. 数据闭环完整
- 不只是“回答问题”，而是把知识库、风险规则、低置信队列、老师审核包串起来。
- 这意味着项目能讲清楚：
  - 为什么拦截
  - 为什么建议补充信息
  - 为什么进入待补知识队列
  - 为什么需要老师确认

### 4. 可验证性强
- 已有可运行前端、后端接口、测试脚本和验收清单。
- 答辩时可以直接展示：
  - 首页 / 系统状态页
  - 风险判断结果
  - 检查清单
  - 老师审核包
  - API 返回与测试证据
- 这比只讲概念更容易拿分。

### 5. 面向真实实验室场景
- 主题天然贴合实验室安全、开工检查、应急处置、培训与管理看板。
- 和“通用 AI 助手”相比，垂直场景更容易体现专业价值。

## 答辩时建议重点突出什么

### A. 业务价值
讲清楚项目不是做聊天，而是减少实验前安全遗漏：
- 避免缺少 PPE、SOP、SDS、设备确认
- 避免高风险实验未经审核就开工
- 避免老师/管理人员事后补救

### B. 技术价值
重点讲这 4 个点：
1. **轻量但完整的架构**
2. **本地知识库 + 风险规则**
3. **低置信问题队列**
4. **老师审核闭环**

### C. 工程价值
展示“不是 PPT 工程”：
- 有前端
- 有后端接口
- 有测试
- 有设计文档
- 有系统状态页和运行证据

## 系统设计 / 实现 / 测试三阶段的卖点

### 系统设计阶段
- 体现“先设计再实现”
- 强调单体模块化架构
- 强调数据库、接口、UI、安全四个维度都做了设计

### 实现阶段
- 体现“可运行、可演示”
- 前后端已联通
- 关键页面已可打开
- 核心接口已可验证

### 测试阶段
- 体现“有回归意识”
- 已有 smoke / logic / risk assess 测试
- 有浏览器自动化验证
- 有接口返回证据

## 你需要和我对接确认的信息
如果要把项目继续打磨得更像“能交付的产品”，建议你确认下面这些信息：

### 1. 典型场景
请给我 3 个最真实的实验场景，例如：
- 化学试剂配制
- 生物样本处理
- 高压设备操作

### 2. 老师审核规则
请确认哪些情况必须老师确认：
- 高风险实验
- 缺少 SOP / SDS
- 缺少 PPE
- 新手独立操作

### 3. 项目命名与口径
请确认答辩时最终使用哪个名字：
- 实验室安全小助手
- Lab Safety Copilot
- 实验安全前置哨

### 4. 展示目标
请确认你更看重哪类答辩结果：
- 偏“技术实现”
- 偏“应用落地”
- 偏“创新创业”

### 5. 是否需要真实数据
如果你想让项目更像真实产品，可以决定是否：
- 使用真实课程场景数据
- 保留匿名化样例数据
- 准备前后对比指标

# Design

## 目标概述
- 本设计服务于“把当前 `web_demo` 从单页堆叠式演示页，调整为更适合展示和演进的侧边栏 + 分区结构”。

## 方案概要
- 一句话方案：
  - 保持现有 FastAPI + 单模板结构不变，在 `index.html` 内重组布局，加入左侧导航和内容分区切换。
- 主流程：
  1. 抽取顶部摘要信息作为总览页
  2. 将功能区拆为若干 view：总览 / 智能问答 / 开工阻断 / 培训与看板 / 事故复盘
  3. 使用侧边栏按钮切换当前激活 view
  4. 保留现有 DOM id 与事件逻辑，优先通过“显示/隐藏分区”的方式减少业务脚本改动

## 关键决策
- 决策 1：
  - 先不引入新的前端框架，仍在原模板内完成结构重组
- 决策 2：
  - 优先复用现有 id 和现有 fetch 逻辑，避免同时改 UI 和接口脚本
- 决策 3：
  - 侧边栏导航采用“总览 / 问答 / 阻断 / 培训看板 / 复盘”五段式结构
- 决策 4：
  - 当前页面先做“分区切换”，不做真正 URL 路由分页

## 影响模块
- 模块 / 文档 / 脚本：
  - `web_demo/templates/index.html`
  - `docs/changes/*`
- 影响方式：
  - 重构页面布局与 section 组织方式，但尽量不动后端 API

## 对展示主线的影响
- 对演示链路：
  - 正向影响。首页更聚焦，主讲时不会被所有模块同时干扰
- 对门禁 / 验证：
  - 需要补至少一轮页面切换与主功能点击验证
- 对答辩材料：
  - 后续更容易说明“系统分模块能力”，而不是一页堆功能

## 风险与取舍
- 风险：
  - 单文件模板较长，改动稍大时容易引入小回归
- 取舍原因：
  - 当前最值钱的是尽快把信息架构收敛，而不是先做技术栈升级

## 未决问题
- 问题 1：
  - 后续是否要把“培训”和“看板”继续拆成两个独立 view
- 问题 2：
  - 本地 Dify 与知识库优化是否作为下一条 change，还是继续并入本 change

## 不做项
- 本次明确不覆盖：
  - React / Next.js 重构
  - 纯本机 Dify 环境搭建
  - 知识库内容大规模重写

## 二、正式一点的邀请模板（适合邮件/文字说明）

老师您好：

我是“实验室安全小助手”项目的成员。目前项目已完成实验室安全问答、风险评估、开工前检查与阻断、培训统计、管理看板等核心模块的阶段建设，并形成了当前统一指标口径：

- 知识库正式导入：`398`
- 正式回归：`20/20`
- 稳定性验证：`3/3 PASS`

当前项目已达到“可演示、可答辩、可继续扩展”的阶段状态。  
下一步我们希望围绕申报书要求，补充真实场景下的试点应用证据、用户反馈和满意度统计。

为此，想邀请您支持一次小规模试点。试点的主要目的不是正式部署，而是：

1. 验证系统在实验室或实验教学场景中的可用性；
2. 收集学生、助教、老师对问答、准入阻断、培训与看板等功能的真实反馈；
3. 形成后续《试点应用效果报告》的基础材料。

### 试点建议形式

- 时间：约 `15~30 分钟`
- 规模：小范围参与（学生、助教、老师）
- 内容：固定问题问答、准入阻断演示、培训/看板简要展示、满意度问卷回收

### 我们这边负责

1. 提前准备试点流程；
2. 准备签到表、问卷和记录表；
3. 控制试点节奏，尽量不影响正常教学；
4. 试点后整理反馈和总结材料。

如果您这边方便支持，我们可以再进一步确认适合的场景、时间和参与对象。  
感谢老师的帮助与指导。

此致  
敬礼

## 三、面对面口头说明提纲（1 分钟版）

如果你要当面跟老师说，可以照这个提纲：

1. 先说明项目当前已经不是纯 demo，而是已经有核心闭环和正式验证口径；
2. 再说明试点不是大规模上线，只是做一个小范围可控验证；
3. 强调试点目的主要是补“真实应用反馈、满意度和问题清单”；
4. 明确不会占用太长时间，通常控制在 15~30 分钟；
5. 表示你们会自己准备流程、问卷和记录，不给老师增加额外负担。

---

## 四、对方常见问题的简短回答

### 1. 试点是不是正式部署？

不是。当前试点主要是验证系统在真实场景中的可用性和用户反馈，不是正式大规模部署。

### 2. 会不会影响正常上课或实验？

我们会尽量把试点安排在实验前说明时间、培训时间或小范围体验时段，控制在 15~30 分钟左右。

### 3. 需要老师额外做很多事吗？

不会。我们会自己准备流程、问卷和记录表，只需要老师帮忙协调场景和参与对象，并给出专业反馈即可。

### 4. 试点后你们要拿什么结果？

主要想拿到：

1. 用户反馈
2. 满意度问卷
3. 试点记录
4. 问题清单与改进建议
